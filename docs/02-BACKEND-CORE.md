# 02 - Backend Core (entry, bridge, config)

The pywebview entry point (now **profile-first** - see [[13-PROFILES-BRANDS]]), the empty `backend` package marker, the 132-public-method `Api` bridge class exposed to JS, and the central settings/config module with its defaults + per-profile identity overlay + user-override overlay.
**Covers:** app.py, backend/__init__.py, backend/config.py, backend/api.py

See also: [[01-ARCHITECTURE]], [[03-BACKEND-DATA]] (database layer), [[04-BACKEND-DOCGEN]] (numbering + generators + PDF engine + signing), [[05-FRONTEND-SHELL]] (app.js bridge), [[06-FRONTEND-EDITORS]], [[07-FRONTEND-SUPPORT]], [[08-STYLES-TEMPLATES]], [[09-DATA-MODEL]], [[13-PROFILES-BRANDS]] (profile_manager, profile_numbering, shared library).

## app.py

**Purpose** - Desktop entry point, now **profile-first**: bootstraps the multi-company profile layout ([[13-PROFILES-BRANDS]]) BEFORE any backend import, then boots the active profile's SQLite DB, runs idempotent migrations, and opens the pywebview (Edge WebView2) window that hosts `templates/index.html` with the `Api` bridge as `js_api`. WebView2 runs with a persistent app-level profile at `%LOCALAPPDATA%/BusinessHub/WebView2` (`private_mode=False`), avoiding pywebview's unreliable shutdown deletion of a temporary `EBWebView` folder while WebView2 metrics files are still locked.

**Key symbols**
- `_hide_console() -> None` - Windows-only. Hides the black cmd/console window, but ONLY if this process owns it (checks `GetConsoleWindow` owner PID == `GetCurrentProcessId`) so it never nukes a parent terminal. No-op under `pythonw.exe`. Called at import time (~line 51), before `main()`.
- `main() -> None` - the boot sequence:
  1. `profile_manager.manager().bootstrap_profiles(legacy_db=data/po_tool.db, legacy_settings=data/settings.json, legacy_assets=static/)` - creates/validates `data/profile-registry.json` and `data/profiles/<id>/`, migrating the legacy single-company layout on first run. On bootstrap failure it sets env vars `DOCUMENTS_HUB_LEGACY_FALLBACK=1` + `DOCUMENTS_HUB_PROFILE_WARNING` and continues on the legacy Abraj data (`Api.get_active_profile()` surfaces the warning to the UI).
  2. ONLY THEN `import backend.database / backend.migrations / backend.api` - these imports live INSIDE `main()`, not at module level, because `backend/config.py` binds profile paths at import time.
  3. `database.init_db()` → `migrations.run_all()` (prints per-step `[migration]` lines). **A failed migration raises `RuntimeError` and aborts launch** - UNLESS `DOCUMENTS_HUB_LEGACY_FALLBACK=1`, in which case failures are logged and boot continues.
  4. Construct `Api()` → `window = webview.create_window(...)` → `webview.start(debug=..., private_mode=False, storage_path=_webview_storage_path(app_dir))`.
- **The launch card (2026-10-20; the doors before it, 2026-10-02).** `main()` calls `launch_gate.start()` FIRST, **before `import webview`** (which sits inside `_main()`) - so the card is on screen ~0.28 s after the click instead of nothing until the window at ~1.4 s. `main()` is a wrapper that calls `_main()` and, on ANY exception, closes the card so an error is never hidden behind it. Stage ticks come from real moments only: `_main()` marks stage 1 after migrations, `window.events.shown` marks 2 (and starts `_warm_start_up(api)` - boot_cache), `window.events.loaded` marks 3, and the page's `Api.gate_ready()` lets the card finish and fade. **The app sends the card no data** - it works out its own rows in its own process (`gate_brief.card()`), so the card costs the app nothing (pinned by `tests/gate_backend.test.py`). **`launch_gate.hold_window(window)`** (after `create_window`, before `webview.start`) keeps the app window invisible while it loads under the card, and `main()`'s error path calls `reveal_window()` so a failed start never leaves it hidden - Opacity 0, faded in by `reveal_window` - see [[03-BACKEND-DATA]] for why NEVER a window region. `launch_gate.note(name)` records those moments with or without a card. Set `DOCUMENTS_HUB_NO_GATE=1` to start without it. See [[03-BACKEND-DATA]] ▸ backend/launch_gate.py.
- `_webview_storage_path(app_dir) -> Path` - a **persistent** WebView2 profile dir at `%LOCALAPPDATA%/BusinessHub/WebView2` (falls back to `app_dir/data/...`). pywebview's default private mode uses a temp profile it deletes on exit; WebView2 can hold `BrowserMetrics` locked past shutdown → noisy access-denied warnings. Passed as `storage_path` with `private_mode=False`. (Guarded by `tests/webview_storage_backend.test.py`.)

**Reads / writes** - Reads env var `ABRAJ_DEBUG` (`"1"` enables WebView2 devtools). Writes env vars `DOCUMENTS_HUB_LEGACY_FALLBACK` / `DOCUMENTS_HUB_PROFILE_WARNING` on bootstrap failure. Loads `templates/index.html` via `Path(...).as_uri()` (a `file://` URL - this is why several bridge methods exist only to work around `file://` XHR restrictions, e.g. `get_lottie`). Triggers profile bootstrap, DB creation and migrations as side effects.

**Calls / called by** - Imports `backend.profile_manager` at module level; imports `backend.database`, `backend.migrations`, `backend.api.Api` inside `main()` after bootstrap. Inserts the app root onto `sys.path` (~line 54) *before* any `backend` import, so running `python app.py` from any cwd works. Entry from `python app.py` / bundled `.vbs` launcher.

**Gotchas**
- Window opens `maximized=True` with `width=1280, height=820, min_size=(1000, 700)`; title `"Business Hub"` (the app's product name since 2026-07-17; neutral because the app is multi-company).
- **Boot order invariant:** `bootstrap_profiles()` must complete before ANY backend module import - `backend/config.py` reads `ACTIVE_PROFILE`/`DB_PATH`/`SETTINGS_PATH`/`ASSETS_DIR` from `profile_manager` at import time. Moving the backend imports above the bootstrap silently points every module at the wrong profile dirs.
- Order also matters for the console: `_hide_console()` runs at ~line 51 (import time) and `sys.path.insert(0, ...)` at ~line 54 - both must precede `main()`'s backend imports (console flash / broken launch when cwd != app dir otherwise).
- **Shutdown crash guard (2026-07-18):** on Windows the WebView2/WinForms teardown can throw `InvalidAsynchronousStateException` (cross-thread call into the closing window) which pythonnet then crashes marshaling (NullReferenceException in `AllocateTypeObject`) → an unhandled-exception dialog on close. `main()` subscribes `window.events.closed += lambda: os._exit(0)` (try/guarded) and also calls `os._exit(0)` after `webview.start()` returns, terminating before the racy finalizers run. Safe because **all persistence is synchronous during use and there are NO `atexit` handlers** - nothing is flushed at exit. Don't add exit-time cleanup without revisiting this (`os._exit` skips it).
- Migration failures are now **fatal** (`RuntimeError`) in normal operation - the old "non-fatal, app still launches half-migrated" behavior only survives under legacy fallback. Migration success/`applied` is only visible on stdout, which the console-hide swallows in production.

## backend/config.py

**Purpose** - Central configuration: hard-coded defaults for every doc type (paths, prefixes, brand colors, company identity, per-type column schemas, table-fitting mm constants, bank info) PLUS two overlays applied at import time: the **company-profile identity overlay** (`_apply_company_profile_defaults()`, Eshraqat rebranding) and then the **user-override overlay** loaded from the active profile's `settings.json`. All paths are **profile-bound** - `config` imports `profile_manager` at the top ([[13-PROFILES-BRANDS]]).

### Module-level constants (the defaults)

- **Profile binding (~lines 25-40)** - `ACTIVE_PROFILE = profile_manager.active_profile_id()` (`"abraj"` or `"eshraqat"`), `PROFILE_DIR = profile_manager.profile_dir()`, `DATA_DIR = PROFILE_DIR` (i.e. `data/profiles/<id>/`), `ASSETS_DIR = profile_manager.assets_dir()` (`data/profiles/<id>/assets`), `PROFILE_ACCENT` (abraj `#1F3864`, eshraqat `#861432`), `IQD_PER_USD` (abraj `1400.0`, eshraqat `1500.0`), `CASH_IQD_PER_USD = 1500.0`, `UNCOSTED_MARKUP = 0.40` (2026-10-21: a line with no cost is costed at price / 1.4 in every profit figure - see `database._line_econ` in [[03-BACKEND-DATA]]; also sent to the editors as profile metadata `uncosted_markup`), `ESHRAQAT_IDENTITY` (`name_lines` English + `name_lines_ar` Arabic + `po_title_ar` + website/emails/brand_color). **`name_lines_ar` and `po_title_ar` are read by the Arabic/RTL eshraqat PO skin only** (`templates/eshraqat/po_page.html` via `header_ar`, [[08-STYLES-TEMPLATES]]); the other four eshraqat documents read `name_lines`. Keep both name lists in sync when the registered company name changes. All recomputed on `importlib.reload(config)` - this is how a profile switch retargets everything.
- **Paths** - `APP_DIR` (repo root), `TEMPLATES_DIR`, `STATIC_DIR`, `DB_PATH` (`data/profiles/<id>/po_tool.db`), `SETTINGS_PATH` (`data/profiles/<id>/settings.json`). **NOT** `data/po_tool.db` / `data/settings.json` anymore - those files are only legacy seeds consumed once by `bootstrap_profiles()`. `DOCUMENTS_ROOT = D:\PO TOOL` (Abraj default; the Eshraqat overlay rewrites it to `D:\ESHRAQAT DOCUMENTS`) is the single base under which all doc trees live.
- **Derived roots** - `PO_ROOT` (`<ROOT>/PURCHASE ORDERS`), `QUOTE_ROOT` (`QUOTATIONS`), `DN_ROOT` (`DELIVERY NOTES`), `INV_ROOT` (`INVOICES`). NOTE the plural mismatch: folder is `QUOTATIONS` but several comments/docstrings say `QUOTATION` - trust the code (`QUOTATIONS`).
- **Prefixes** - Abraj defaults: `PO_PREFIX="A"`, `QUOTE_PREFIX="QUT"`, `DN_PREFIX="DN"`, `INV_PREFIX="INV"`. Under the eshraqat profile the overlay rewrites them to `PO`/`QT`/`DN`/`IV` (used with flat counters - see `profile_numbering` in [[13-PROFILES-BRANDS]]).
- **`MONTH_FOLDERS`** - `{1:"JAN",...,12:"DEC"}`. Used by numbering modules to build month subfolders.
- **PO table-fitting** - `PO_AUTOFIT=False`, `TABLE_HEADER_MM=12`, **`TABLE_MIN_ROW_MM=10.3`** (was 7 until 2026-09-05; it is now the height the page actually DRAWS, not a paginator-only guess - see [[04-BACKEND-DOCGEN]]), `TABLE_LINE_HEIGHT_MM=5.5`, `PO_SIGNATURE_MM=54.0`. Consumed by `pdf_generator` row-height + page-budget math ([[04-BACKEND-DOCGEN]]). **`MAX_ITEMS_PER_PO` and `TABLE_BUDGET_MM` were retired 2026-07-29** when POs started paginating instead of splitting; the per-page budget is now derived per page ROLE from measured geometry in `pdf_generator`. Stale keys in an existing `settings.json` are ignored on purpose.
- **`BRAND_COLOR="#002060"`**, `COMPANY` (Arabic/English name lines + PO signature labels/names).
- **`USER_PREFERENCES`** - app-wide UI preferences persisted under the active profile's `settings.json` `preferences` block: `theme`, `after_export`, `compact_tables`, `dn_prices_default`.
- **Quote** - `QUOTE_TYPE_CODES`, `QUOTE_ADDRESS_OPTIONS` (`["CSSP Site","IBRU"]`), `QUOTE_CLIENTS_SEED`, `QUOTE_TERMS_DEFAULT` / `_EQUIPMENT` / `_MANPOWER`, `QUOTE_BRAND_COLOR="#1F3864"`, `QUOTE_COMPANY`, `QUOTE_TABLE_AREA_MM=120` / `QUOTE_MIN_ROW_MM=12` / `QUOTE_MAX_ROW_MM=55`, and **`QUOTE_TYPES`** (per-subtype schema: materials/equipment/manpower/service, each with `code`, `label`, `grand_total`, `terms`, `primary_key`, `columns`).
- **DN** - `DN_BRAND_COLOR`, `DN_COMPANY`, `DN_ADDRESS_OPTIONS` (copied from quote), `DN_BASE_COLUMNS`, `DN_PRICE_COLUMNS` (Rate/Total appended only when `include_prices`).
- **INV** - `INV_BRAND_COLOR`, `INV_WITHHOLDING_PCT=3.3`, `INV_COMPANY`, `INV_TYPE_CODES`, `INV_ADDRESS_OPTIONS`, `CASH_BANK` (~line 390, the cash-payment bank dict) and `INV_BANK_INFO` (list of bank dicts including `CASH_BANK`; the `"cash"` key is a sentinel that omits the Payment Info card), `INV_TYPES` (per-subtype schema like quotes but no `grand_total`/`terms`).
- **Column-kind vocabulary** (shared across all schemas): `text` (wraps, counts toward row height), `num`, `money` (`$X.XX`), `computed` (qty*rate), `image` (base64 cell), `index` (auto "NO." column).
- **Override holders (start empty, filled by overlay)** - `QUOTE_LAYOUT`, `DN_LAYOUT`, `INV_LAYOUT`, `QUOTE_SUBTYPES_OVERRIDES`, `INV_SUBTYPES_OVERRIDES`, `DN_BASE_COLUMNS_OVERRIDE`.

### Functions

- `_apply_company_profile_defaults() -> None` (~line 497, called at ~line 578 **BEFORE** `_apply_user_settings`) - the Eshraqat identity overlay. No-op when `ACTIVE_PROFILE != "eshraqat"`; otherwise rewrites: `DOCUMENTS_ROOT = D:\ESHRAQAT DOCUMENTS` (re-deriving all doc roots), prefixes to `PO`/`QT`/`DN`/`IV`, all brand colors (`BRAND_COLOR`/`QUOTE_BRAND_COLOR`/`DN_BRAND_COLOR`/`INV_BRAND_COLOR`) to `PROFILE_ACCENT`, all COMPANY name-lines to `ESHRAQAT_IDENTITY`, `INV_BANK_INFO = [CASH_BANK]`, and empties `QUOTE/DN/INV_ADDRESS_OPTIONS`. User `settings.json` still wins over all of it (it runs afterwards).
- `load_user_settings() -> dict` - parse the active profile's `settings.json` (`SETTINGS_PATH`); returns `{}` on missing/unreadable (never raises).
- `_apply_user_settings() -> None` - the overlay engine. **Mutates ~30 module globals** based on the settings JSON. Handles: flat top-level keys (PO/legacy + `documents_root` + `ui_lang`), app `preferences`, per-doc-type sections (`quotation`/`delivery`/`invoice`) merging COMPANY blocks, brand colors, address options, layout dicts, per-subtype overrides, DN column override, invoice bank list, and withholding pct (auto-syncs the tax label). Called once at module bottom, after `_apply_company_profile_defaults()`.
  - Inner helpers: `_merge_company(base, override)`, `_layout_dict(raw)` (extracts `max_items`/`budget_mm`/`min_row_mm`/`safe_gap_mm`/`autofit_rows`), `_subtype_overrides(sec, valid_keys)` (extracts `terms`/`column_heads`/`columns`/`layout` per subtype; validates column `kind` against `{text,num,money,computed,image,index}`).
- `save_user_settings(settings: dict) -> None` - write the dict to the active profile's `settings.json` (creates parents, `ensure_ascii=False`, indent 2). **Full replace of the file** - callers (`Api.save_settings` / `save_doc_settings`) do the merge themselves before calling this.
- `current_effective_settings() -> dict` - snapshot of every tunable as it currently stands (flat PO keys + `preferences` + `quotation`/`delivery`/`invoice` sections, subtype overrides spread in, plus `profile_id` and `logo_data_uri`). This is what `api().get_settings()` returns.

**Reads / writes** - Reads the active profile's `settings.json` (`SETTINGS_PATH`), including the top-level `preferences` block used by app UI settings such as dark mode. Writes it via `save_user_settings`. Defines `ASSETS_DIR/logo.png` location (written by `Api.upload_logo` - per-profile, no longer `static/logo.png`). All on-disk doc roots originate here.

**Calls / called by** - Imports `profile_manager` at the top (the ONLY backend module config depends on - see [[13-PROFILES-BRANDS]]). Imported by nearly every backend module. `Api.save_settings`/`reset_settings`/`save_doc_settings` call `importlib.reload(config)` to re-run both overlays and then reload generator modules that captured config at import time; `Api._reload_profile_runtime` reloads it first among 16 modules on a profile switch or backup restore.

**Gotchas**
- **Import-time mutation:** profile binding, `_apply_company_profile_defaults()` and `_apply_user_settings()` all run at import. To pick up a changed `settings.json` OR a profile switch you MUST `importlib.reload(config)` - the Api methods do this, but any long-lived reference to `config.QUOTE_COMPANY` etc. captured before a reload goes stale.
- **Overlay order is load-bearing:** `_apply_company_profile_defaults()` (~line 578) runs BEFORE `_apply_user_settings()` so user settings always win over the Eshraqat identity defaults. Keep that call order.
- **`settings.json` is per-profile:** writing `data/settings.json` directly does nothing at runtime (it is only the legacy bootstrap seed) - use `config.SETTINGS_PATH`.
- **Never hardcode the USD peg:** `config.IQD_PER_USD` is profile-dependent (1400/1500) and `CASH_IQD_PER_USD=1500` covers cash deals; both are recomputed on reload.
- **User preferences are top-level settings:** theme/behavior prefs live in `settings.json.preferences`, not in a document section. `Api.save_settings({"preferences": ...})` shallow-merges that whole block; callers should send the complete current preference object.
- **PO company classification (2026-07-17):** `config.PO_COMPANY_TAGS` (`{name: "client"|"internal"}`, from `settings.json.po_company_tags`, per profile) tags each PO "لشركة" name; `config.po_company_is_internal(name)` returns True only for an explicit `internal` (untagged ⇒ client). Surfaced in `current_effective_settings()`. Bridge: `Api.get_po_company_tags()` (seeds via `database.seed_po_company_tags` on first read) and `Api.set_po_company_tag(name, tag)` - **read-modify-write ONE key** then updates `config.PO_COMPANY_TAGS` in memory (the popup path); `save_settings`' top-level shallow merge would clobber the whole map, so the single-key upsert must NOT go through it. The Settings editor bulk-saves the full map via `save_settings({po_company_tags: ...})`. Drives the To-Do `deliver` bucket ([[03-BACKEND-DATA]] `pos_awaiting_invoice`). **2026-10-21 - ONE copy:** the map lives in `purchase_order.company_tags` (what PO Settings edits and config reads); `database.read_po_company_tags(settings)` / `write_po_company_tags(settings, tags)` are the only reader/writer, and the writer drops the old top-level `po_company_tags`. The PO editor's prompt used to read/write that old copy and REPLACE the live map with it - on Abraj it still had ابراج البدر as client, so one prompt answer put every our-company PO in the To-Do. Cancelling the prompt now saves nothing (it used to save "client", filing typos like v/j/ت as clients). Pinned by `tests/po_company_tags_one_copy.test.py`.
- **Reload fan-out:** generators (`pdf_generator`, `quote_generator`, `dn_generator`, `inv_generator`) capture config values at their own import time, so `reset_settings`/`save_doc_settings` reload them too. `save_settings` (top-level) does NOT reload the generators - only config. Any new module that captures config at import time must be added to BOTH those reload loops AND `Api._reload_profile_runtime`'s 16-module reload list, or it goes stale after settings saves and profile switches.
- **Column widths are hand-tuned to sum near a magic total** (data columns ≈96.4 for quote leaving 3.6 for the NO. column; INV ≈95.4 leaving 4.6). Changing one width without rebalancing skews the PDF table. See per-schema comments.
- **`documents_root` cascade:** setting it re-derives QUOTE/DN/INV roots (and PO root, unless `po_root` is explicitly pinned). Setting `po_root` overrides just PO.
- **Withholding label auto-sync:** overriding `invoice.withholding_pct` also rewrites `INV_COMPANY["tax_label"]` - don't also hand-set the label expecting it to stick.
- **`DN_BASE_COLUMNS_OVERRIDE` is base-only** - Rate/Total (`DN_PRICE_COLUMNS`) are appended at render time when `include_prices`, never stored in the override.
- **Remembered item costs are stored in USD (2026-08-05).** `_cost_to_usd_for_memory(raw, currency, peg)` + `_item_memory_payload(row, primary, image_keys, cost_currency, cost_peg)`. The item memory is **shared across every document of a type**, so a cost typed into a dinar quote and replayed into a dollar one was wrong by the exchange rate - 84,000 landing where 60 belongs. `remember_inv_item` already normalises `rate` for exactly this reason; costs never got the same treatment.
  - **`cost_usd` is both the value and the marker.** Entries remembered before this change have a raw `cost` in an unrecorded currency that cannot be recovered, so the editor autofills only entries carrying `cost_usd` and skips the rest - the user's explicit choice over guessing. The raw `cost` key is **dropped**, not kept alongside: leaving it there is an invitation to read it as dollars.
  - **`save_quote` reads the currency from the PAYLOAD** (`cost_currency` / `cost_iqd_per_usd`), not from `doc_cost_meta`. quote.js calls `set_cost_currency` only **after** `save_quote` returns, so a database read during the save sees the previous value.
  - `_item_memory_payload` was extracted from the inline block specifically so the test could call the real thing. While it was inline the test had to reimplement it, and a mutation that dropped the `data.pop("cost")` went undetected.
  - **The same payload now teaches a brand-new Master Data record its money (2026-08-20).** The document row calls the fields `cost` and `rate`, while `master_items.remember` reads `cost_native`/`cost_native_ccy` and `price_native`/`price_native_ccy`. The missing bridge meant a first save imported name, description, unit and picture but left both money fields blank. `_item_memory_payload` now emits both contracts: `cost_usd` remains for safe cross-document autocomplete, the native cost pair preserves exactly what was typed, and `rate` also emits a USD native price (IQD invoice rates are converted before the builder is called). Pinned by `tests/master_items_stay_current.test.py`.
- **`get_item_image(ref)` / `item_image_store_size()` (2026-08-05)** - read a remembered item picture back out of the content-addressed store ([[03-BACKEND-DATA]]). Needed because the front end runs over `file://` and cannot read a local file itself, the same constraint `get_lottie` exists for. Both swallow every exception: a picture that has been deleted, or a store on an unreadable disk, must degrade to "no picture" rather than throw across the bridge and break the autocomplete pick.
- **`get_cost_rate` / `set_cost_rate` (2026-08-05)** - bridge methods for the per-document cost exchange rate ([[03-BACKEND-DATA]]). `set_cost_rate` validates through the same `_sane_peg` band as the invoice sell rate, because the whole document's profit is derived from the number. **New bridge methods, so an app RESTART is required** - and the editor feature-detects the method before calling it, since F5-without-restart pairs new JS with old Python and an unguarded call throws inside the quote loader and stops the document opening at all.
- **A PO row with a PICTURE is ~3x a text row, and the paginator has to know (2026-08-05).** `pdf_generator.estimate_row_height_mm` sized a row from its text alone; the PO gained a per-row image column ([[05-FRONTEND-SHELL]]), so it now returns `max(text_height, PO_IMAGE_ROW_MIN_MM)` (22mm, mirroring the quotation's `Q_IMAGE_ROW_MIN_MM`). `row_has_image` / `any_row_has_image` decide whether the printed table carries the column at all.
  - **The failure this prevents is narrow but ordinary.** Blind to images, ten picture rows land on one page and the table runs to ~246mm against a signature block starting at 233mm - printed straight over the last rows. Below ~8 rows a PO fits anyway; from ~12 the text estimate already forces a break. **8–11 rows is the whole window**, and it is a very normal purchase order.
  - **`PO_IMAGE_ROW_MIN_MM` also feeds `--po-img-mm`**, which caps the printed picture ([[08-STYLES-TEMPLATES]]). The two must agree: the estimate books the space, the CSS stops the image exceeding it. A consequence worth knowing when testing - **zeroing the constant to prove the reserve matters shrinks the pictures to nothing and proves the opposite.** Patch `estimate_row_height_mm` itself instead; `tests/po_image_column.test.py` does.
  - The reserve is deliberately generous: a picture actually renders ~16.9mm (capped by the 11% column **width**, not the height), so a row is ~18.2mm against 22mm booked. That matches the module's stated policy of over- rather than under-estimating.
- **New document numbers are HELD while the save runs (multi-user Phase 1, 2026-10-22).** `save_inv` / `save_quote` / `save_dn` / `save_po` take a new number through `number_claims` ([[03-BACKEND-DATA]]): an auto number via the numbering module's `claim_next_*_number`, an editor-proposed one via `number_claims.claim`; `confirm` right before the success return, `release` in the `except`. A number another person took a moment ago returns `{ok: False, number_taken: True, doc_no, error}` (`_number_taken`) - the four editors key on `number_taken`, toast it and fetch the next number (`refreshInvNumber` / `refreshQuoteNumber` / `refreshDnNumber` / `initNextPoNumber`; `tests/number_taken_editors.test.js`). Edits of an existing document, and `save_po` over an existing PO, claim nothing - that is an overwrite of the same document.
- **A document may only name a client that is ON FILE (2026-09-11).** `save_quote` / `save_dn` / `save_inv` each call `_known_client_error(client_name, existing)` before anything else and return its refusal unchanged. The refusal carries **`unknown_client`** - the editors key their add-a-client dialog on that field, not on the message. Two things it must never do: refuse a name an ALREADY SAVED document carries (one of the 180 documents on file names a client who is not in Master Data, and locking the list must not make it uneditable), or block a save because the client store could not be read - a save is the user's work, and losing it to a broken index is worse than letting one through. Both are pinned by `tests/client_must_be_on_file.test.py`.
- **An edited date must move the PDF (2026-08-02).** `save_quote` / `save_dn` / `save_inv` used to pin the file to its existing folder on re-save while writing the DB row with the **edited** date's `year`+`month`. The month lists join those two (`entry["editable"] = doc_no in db_rows` in `list_quotes_for_month` and friends), so a date change across a month boundary left the document **view-only in the old month** (file found, no DB row) and **absent from the new one** (DB row, no file) - editable from neither. All three now call **`_edit_target_folder(old_pdf_path, dated_folder)`** → `(folder_to_use, stale_file)` and then **`_drop_stale_pdf(stale, out)`** after the record is written.
  - `_drop_stale_pdf` deletes **only** once the new file is confirmed on disk - a duplicate is recoverable, a deleted-and-not-rewritten document is not.
  - Comparison goes through `_same_dir` (`os.path.normcase`, trailing-separator tolerant). Windows paths vary in case constantly; a naive compare would treat every save as a move and delete a live file.
  - Any folder change counts, not just the month, so changing the client or document type relocates the PDF too.
  - **`_signed_copy_dest` deliberately still reads `Path(rec["pdf_path"]).parent`** - the client's scanned copy belongs beside its DN. It is tracked by an absolute path in `signed_copies`, so it keeps resolving after a DN moves month; it just stays in the old folder. Tidy-up not implemented.
  - **POs are different.** `save_po` files by `date.today()` (the day folder) while recording the doc date's month, so a back-dated PO is *expected* to sit in a folder whose month differs. Do not "fix" that by moving the file: PO numbering scans only the current + previous month folders, so removing a PO from them lets the counter re-issue its number. Quote/DN/INV numbering scans the whole root and is unaffected. See `tests/edit_date_moves_file.test.py`.
  - **2026-09-02 - the same symptom came back, and this half was innocent.** Waleed reported that editing an invoice's date and saving changed nothing: same folder, same date in the PDF. `save_inv` was correct end to end (verified on a sentinel invoice: JUL folder to SEP folder, old file dropped, DB `year`/`month` rewritten, PDF re-rendered with the new date). The edited date simply never reached it - the EDITOR never put it in the payload. Fixed in `app.js bindDocDate` [[05-FRONTEND-SHELL]]. **When a "the save ignored my edit" report arrives, check the editor hands the value over before reading anything here.**
- Plural folder gotcha noted above (`QUOTATIONS` on disk vs `QUOTATION` in comments).

## backend/api.py

**Purpose** - The pywebview `js_api` bridge: class `Api`, **132 public methods** (plus 2 private: `__getattribute__` and `_reload_profile_runtime`), each public one callable from JS as `await window.pywebview.api.<name>(args)`. Python `snake_case` maps directly to the JS call name. Almost every method is a thin adapter over `database`, the numbering modules (`*_numbering` + `profile_numbering`), the generators, `signing`, `clients`, `analytics`, `data_manager`, `profile_manager`, or `spreadsheet_parser`, and returns plain dicts/lists (JSON-serializable) - most save/action methods return `{"ok": bool, ...}` and swallow exceptions into `{"ok": False, "error": str(e)}`.

Dashboard, month-list, analytics, and costing responses pass through `_bridge_json_safe()` before crossing the bridge. It recursively replaces non-finite floats (`NaN` and positive/negative `Infinity`) with `0.0`; Python's JSON encoder permits these values by default, but WebView2's strict `JSON.parse` rejects them and can leave the frontend call waiting indefinitely.

It resolves the peg in priority order: **the rate the editor sent** (`inv["sell_iqd_per_usd"]`, run through `_sane_peg`; 2026-08-04), else `config.CASH_IQD_PER_USD` when `payment_bank_key == "cash"`, else `database.doc_iqd_per_usd("inv", inv_no)` - that last one because `_cash_deal_index` cannot see an invoice that is not saved yet. - **`_sane_peg(value) -> float | None` (2026-08-04)** - module-level guard for a typed exchange rate. Accepts a plain or comma-grouped number inside `_PEG_MIN`..`_PEG_MAX` (100 – 100,000); returns `None` for anything else so `save_inv` **falls back** rather than failing. The band is deliberately wide - it exists to catch a decimal slip (`1.5`) or an extra zero (`15000`), not to have a view on the market. The blast radius justifies it: `grand_total` is derived from this number and is SUMmed by analytics, the dashboard revenue series and the clients page, so one bad value misprices an invoice everywhere at once with nothing on screen to show for it. Unlike costs (converted on every read) **this conversion is frozen at save time**. It also normalises each row's `rate` back to USD before `remember_inv_item` / `remember_doc_columns` - both memories are shared across every invoice of the type, so a dinar rate stored raw would resurface as a ~1400x price on the next dollar invoice (`inv.js invSellFromUsd` converts it back on pick).

**Gotchas**
- **JS name = Python name verbatim** (pywebview does NOT camelCase). `save_quote` → `api().save_quote`. Renaming a method breaks the frontend call site silently (JS just gets `undefined is not a function`).
- **The `__getattribute__` lock only covers public callables** - long-running work must live in public methods for the profile-switch lock to protect it, and `_`-prefixed helpers bypass it. Do not add a public method that holds the lock forever (`switch_profile` takes the same RLock - it would deadlock a switch, RLock reentrancy notwithstanding, or starve it).
- **Save-time renumbering:** `save_quote`/`save_inv`/`get_next_*` recompute the number at save from the current DB max (abraj) or the flat `document_counters` floor (eshraqat, via `profile_numbering.peek`). Two saves without an intervening record can collide; edit mode (`is_edit`) is what preserves an existing number+folder. Editing a doc's DATE relocates NEW docs' folders but edits keep the original folder (they read `pdf_path` parent).
- **`profile_numbering` counters are tombstone-aware:** the floor is `max(counter, live table numbers, deleted_docs tombstones)+1`, so deleted numbers are permanently retired - do not "fix" apparent gaps. `commit()` (called after a successful save, idempotent MAX upsert) requires consecutive-integer batches - `save_po` child splitting relies on `peek_many` producing them.
- **Cost inheritance on re-save:** every `save_quote`/`save_dn`/`save_inv` calls `database.inherit_costs(old_rows, new_rows, primary_key)` so a normal editor re-save never wipes costs entered in the costing workspace. If you change the primary_key mapping, cost inheritance breaks silently.
- **`pull_costs_from_quote` currency conversion** is load-bearing: a cost is stored in the unit its OWN ROW records (`cost_ccy`, falling back to the doc's entry currency); forgetting the USD/IQD conversion - or doing it at the document's flag when the row says otherwise - makes profit off by the peg factor (~1400×). Use the **deal** peg on both sides (`doc_iqd_per_usd`), never a bare constant, and always write the unit back with the number.
- **The USD peg is profile- AND deal-dependent** - `config.IQD_PER_USD` (Abraj 1400 / Eshraqat 1500) and `config.CASH_IQD_PER_USD` (1500, used when a deal's invoice is paid in cash). Both are recomputed on `importlib.reload(config)`, and `_reload_profile_runtime` reloads `config` **before** `database`, so `database.IQD_PER_USD` follows the active profile. Never hardcode the number.
- **Image cells are stripped from autocomplete memory** (`remember_quote_item`/`remember_inv_item` drop `kind=="image"` columns) - without this an EQ quote row (base64 image) bloats the DB 200KB+/row.
- **`save_po` no longer splits** (2026-07-29) - one PO, one PDF, N pages; it drops the `filled`/`index` keys before render. `saved` is still a one-element list. `update_po` was always an in-place single-PO re-save, and it always rendered ALL rows into one PDF - which is why an oversized PO re-saved before this change produced a PDF whose page 2 carried a *different* PO number.
- **`list_*_for_month` treat the filesystem as truth** and the DB only for editability/metadata - a PDF on disk with no DB row shows as non-editable (view-only), sorted in by file mtime.
- **Broad try/except → `{ok:False,error}`** everywhere; a failing save returns an error dict, not an exception. Callers must check `.ok`. Some list methods swallow errors into empty lists (`list_link_candidates`, `list_quote_numbers`, `list_quote_refs`) - a failure there looks like "no data".
- **`soft_delete_file` never touches the DB** - use `delete_document` for actual saved document deletion. Calling the file-only helper from an editor Open list leaves dangling active rows that still appear in Costing/To-Do; calling DB-only deletion leaves view-only PDFs.
- **pywebview file-dialog `file_types` regex** is strict (Phase M.3): descriptions can't contain slashes and every extension must be word-chars; `*.*` is rejected. See `bulk_pick_spreadsheet`.
- **`get_lottie` exists only because of `file://`** - lottie's own XHR path-loading is blocked under the `file://` origin, so animations are served through the bridge.
