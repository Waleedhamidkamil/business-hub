# Frontend Editors - Quote / DN / Invoice + shared Open panel

The three non-PO document editors (Quotation, Delivery Note, Invoice) plus the persistent right-side Open/browse panel reused across all doc types. (Official Letter was a fourth until it was retired on 2026-08-27 - see [[01-ARCHITECTURE]].)

**Covers:** static/quote.js, static/dn.js, static/inv.js, static/open_panel.js

> Related: [[01-ARCHITECTURE]] (pywebview bridge, boot, `ALL_VIEWS`), [[05-FRONTEND-SHELL]] (PO editor - the sibling these three mirror), [[13-PROFILES-BRANDS]] (multi-company profiles - where the schemas/labels/pegs these editors receive actually come from), [[07-FRONTEND-SUPPORT]] (`setupGridPaste`, `bulkPasteRegister`, `wireUniversalAutocomplete`, `readEditorColWidths`, `smartMapRow`, `reconcileImportedCostCurrency`, `showTypeRail`, `signingRegister`, `renderChipRow`, `countByKey`, `uniqueSortedKeys`, `showImportPreview`, `afterExportPdf`, submit-button helpers), [[05-FRONTEND-SHELL]] (`api()`, `toast`, `showModal`, `withLoading`, `esc`, `safe`, `hideAllViews`, `setBrand`, `state.today`, chip/mode helpers, `displayToIso`/`isoToDisplay`), [[03-BACKEND-DATA]] / [[04-BACKEND-DOCGEN]] (bridge method implementations, generators), [[09-DATA-MODEL]] (quotes, quote_items, dns, dn_items, invoices, inv_items, doc_cost_meta, submitted_docs).

## Shared shape (read this first)

All four editors are near-identical clones with the same lifecycle; differences are called out per file. Common pattern:

- A module-level `xState` object holds `type`/`lang`, `schema`, `rows`, `columns`, `mode` (`"new"`/`"edit"`), `editXNo`, `dirty`, `initialized`, `numberOverridden`, `signingOverlay`; QUT/DN/INV also carry `layoutDefault` + `autofitRows`. In **all four** editors `dirty` is an `Object.defineProperty` accessor near the top of the file that auto-calls `refreshXSaved()`/`setUnsavedChip` on every assignment - don't `delete` or shadow it, and don't add manual refresh calls assuming plain-field semantics.
- **Profile awareness**: these five files contain almost NO profile branching. Profile differences (column schemas, labels, address options, banks, pegs) arrive pre-resolved via the backend (`get_x_defaults`/`get_x_types` - see [[13-PROFILES-BRANDS]]). The single frontend exception is the **typeless-family guard** in the quote.js/inv.js open-panel filters (Phase Y.3, below).
- `initXModule()` runs once at bootstrap (from app.js): pulls defaults + type schemas, populates datalists/month-selects, wires action buttons via `safe(fn, label)`, exposes public fns on `window`. The visible editor toolbar order is universal: New, Save, Export, optional import/hand-off, optional **Fill from Master Data** (QUT/DN/INV), Preview, Print, Sign, optional Workflow, Fit columns, Fit rows, optional Cost/DN Prices, Settings; the old Open buttons are removed in favor of the persistent right panel and Ctrl+O shortcuts. Workflow exists only for PO/DN/INV and tracks PO fulfillment, not quotation deal links ([[07-FRONTEND-SUPPORT]]).
- **Fill from Master Data (2026-08-14)** - QUT/DN/INV wire `#btnQMasterFill` / `#btnDnMasterFill` / `#btnInvMasterFill` to `window.openMasterDataFill(...)`. The popup resolves the current table in one bridge call, shows matches and alternatives, and provides one checkbox each for Item, Description, Unit, Price and Cost; available fields start checked. Applying changes only the selected fields on matching rows, marks the document dirty, and does not save automatically.
- **Master–detail type rail** (QUT/INV): `enterXType(key)` switches sub-type, stashing only dirty outgoing QUT/INV work into `xState.drafts[oldType]` and restoring the incoming dirty draft. Clean saved/finished docs are discarded so their custom columns do not leak into the next "New" doc. `showTypeRail(...)` (from [[07-FRONTEND-SUPPORT]]) renders the rail with unsaved-draft dots. DN has no sub-types (single `enterDnEditor()`).
- **Rows**: `addXRow(data)` appends one row keyed by column keys; a trailing empty row is auto-added when the last row gains content (`hasXContent`). `buildXRowTr(i)` builds a `<tr>`; `wireXRow(tr)` attaches input/paste handlers; `fullRenderXRows()` re-renders all.
- **Columns (Phase T)**: `xState.columns` is THIS document's own column layout (renamed headers + custom columns), seeded from the current effective defaults for new docs, or loaded from `rec.columns` for saved docs (falling back to the effective schema for un-migrated docs). Header cells carry inline `+` (insert after) / `×` (remove) controls plus an editable `<input>` header. Editing columns NEVER mutates the type schema.
- **Auto-fit row height (per-document layout)**: QUT/DN/INV have a visible toolbar toggle (`#btnQAutofit`, `#btnDnAutofit`, `#btnInvAutofit`). Fresh docs use the doc-type default from `get_*_defaults().layout`; loaded docs use `rec.layout.autofit_rows` when present; payloads always send `layout: {autofit_rows: true|false}` so explicit off is saved per document.
- **Fit columns (content-aware widths, Phase X.25)**: QUT/DN/INV each have a **Fit columns** toolbar button next to Auto-fit (`#btnQFitCols`/`#btnDnFitCols`/`#btnInvFitCols`; PO has `#btnPoFitCols`). It calls `window.fitEditorColumns("#xThead", {pdf})` ([[07-FRONTEND-SUPPORT]]) - one click measures the text in each column and redistributes width so long-text columns get more room and short ones (Qty/Unit) shrink, but **never below what their header word needs at print scale** (so labels like RATE/TOTAL don't break to "RAT E"/"TOTA L" in the PDF), replacing the drag-then-preview loop. Each editor passes its print geometry (`pdf:{widthMm,headerFont}`) so the header floor is measured at the real print font (quote passes `widthMm: 186` with a bold 10pt Bahnschrift header font). It writes the SAME inline `%` a manual drag would, flags the doc dirty, and the widths persist via `col_widths` exactly like a manual resize. Image and synthetic-COST columns are left untouched. Wired once per editor via `window.wireFitColsButton(...)`. This is a horizontal (width) counterpart to the vertical Auto-fit-rows toggle - the two are independent.
- **Autocomplete**: primary column → rich `suggest_x_items(...)`, whose payload now comes from the ONE `master_items` record and fills name, description, unit, price, cost and picture; non-primary text/num/money columns → `wireUniversalAutocomplete(...)` (fills only that cell). The picker maps canonical Master Data money through the shared currency helpers instead of copying storage keys as columns.
- **Save/preview/print**: `validateX()` → `buildXPayload()` → `api().preview_x` / `api().save_x` / `api().print_file`. `preview_x` renders the PDF and returns `{ok, path}`; print re-renders then sends `path` to the printer. Save does a uniqueness check (`check_x_exists`) unless editing the same number.
- **Save modes**: `{stay:true}` keeps the editor open and flips into edit mode; `{stay:false}` (Export) runs `window.afterExportPdf(path, no)` then resets to a fresh doc.
- **Grid paste / bulk paste**: each editor registers with `setupGridPaste` (Excel paste + Ctrl+Z undo via deep-clone snapshot/restore) and `bulkPasteRegister` - both from [[07-FRONTEND-SUPPORT]]. The `_wireXGridPaste()` wiring runs at module load guarded by `document.readyState` - it silently no-ops if the tbody isn't in the DOM yet (all four editors, not just DN).
- **Signing**: each registers with `signingRegister({docType, getOverlay, setOverlay})`; `signing_overlay` flows through the payload.
- **COST column (2026-07-24 - always on).** Quotation, DN and Invoice each append a synthetic `{key:"cost", kind:"money", _synthetic:true}` column as the **LAST** column in `quoteRenderColumns()` / `dnRenderColumns()` / `invRenderColumns()`. The old per-editor toggle (`enterCosts` state, `toggle*Costs`, `set*CostsToggle`, `_sync*CostBtn`, `window.open*Costs`) and its three toolbar buttons are **gone** - don't reintroduce a gate. **Why it's still safe to print:** the column is bound to each row's hidden `cost` field and is only ever in the *render* column list; the save payload and `has*Content()` both use the SCHEMA lists (`editableColumns` / `dnColumns` / `editableInvColumns`), so cost never enters `columns`, never reaches a generator, and a cost-only row is not treated as content. Styling: `.qc-cost-col` on the header, body cells and the invoice tfoot pad ([[08-STYLES-TEMPLATES]]). The USD/IQD header switch is unchanged. **Invoice tfoot math:** `costFootCell` is now unconditional - body and both footer rows are all `cols.length + 3` cells wide (NO + cols + COST + del).
- **Open panel**: `xOpen()` just calls `window.OpenPanel.focusSearch()`; the actual list lives in the shared panel (see open_panel.js). There is no visible editor Open button anymore, but Ctrl+O still routes here. `refreshXList()` fetches `list_x_for_month(y,m)` and renders filter chips + rows. PO/QUT/DN/INV cards delegate their badge to `window.panelStatusHTML`: incomplete-price QUT/INV drafts show `! No PDF` and omit Open/Folder/Copy/Print/Submit (plus invoice Paid), Submitted has no pill (the button changes label), submitted quotations suppress Signed, linked DNs show Linked, paid invoices show Paid and keep it beside Linked when applicable, and a later stage suppresses Signed only in the panel. The editor top-right signing chip still reflects the preserved overlay.
- **Duplicate hook `xMakeDuplicate()` (2026-08-04)** - each editor exposes `window.quoteMakeDuplicate` / `dnMakeDuplicate` / `invMakeDuplicate` (PO's `poMakeDuplicate` lives in app.js). The shared `window.duplicateDocument(kind, no)` ([[05-FRONTEND-SHELL]]) calls `load*ForEdit(no)` and then the hook, which turns the just-loaded document into a **new, unsaved** one. Each hook returns the new number.
  - **All four clear the same identity:** `mode → "new"`, `edit*No → null`, `signingOverlay → null` + `xRefreshSignChip()`, `window.__currentEditorDoc → null`, `setModeChip(false)`, date → today (state **and** the `#qDate`/`#dnDate`/`#invDate` input), then `await refresh*Number()`, `refreshXSaved()`, and finally `dirty = true`.
  - **`numberOverridden = false` is load-bearing in all four English editors.** `load*ForEdit` sets it **true**, and `refresh*Number()` is a **no-op while it is true** - forget the reset and the duplicate silently keeps the original's number, then Save overwrites the document you copied. It also lets QUT/DN/INV re-derive the number if you change the client afterwards, which matters because those numbers embed the client code.
  - **Per-kind provenance:** `invMakeDuplicate` clears `invState.sourceDn` (the transient Make-Invoice link - the copy was not made from that DN); `dnMakeDuplicate` and (2026-08-27) `invMakeDuplicate` re-run `reloadDnSignedCopy()` / `reloadInvSignedCopy()` so the client's returned signed copy is re-read for the NEW number instead of showing the original's. **`sourceQuote` is deliberately kept** in both - the copy belongs to the same deal. Invoice `paid` needs no clearing: it is keyed by invoice number in a separate table, so a new number is unpaid by construction.
  - **Internal Reference is never provenance:** quote/DN/invoice duplicates explicitly clear `#qReference` / `#dnReference` / `#invReference` (as PO does in app.js), while New also clears and load restores `rec.reference || ""`. The value is trimmed into each save payload but the backend strips it before rendering.
  - Each list renderer gains `${x.editable && window.duplicateBtnHTML ? window.duplicateBtnHTML("kind", no) : ""}` in `.row-actions` plus `window.wireDuplicateButtons(box)` - **gated on `editable`** because a view-only row has no DB record to load.
  - **`load*ForEdit` must set `window.__currentEditorDoc` AFTER its own `hideAllViews()` call (fixed 2026-08-04).** All three English loaders originally set it near the top, before the view swap - and `hideAllViews()` nulls it ([[05-FRONTEND-SHELL]]). `duplicateDocument` reads it back to confirm the source actually loaded, so the guard failed and **Duplicate did nothing at all on quote/DN/invoice**; only PO worked, because it assigns twice. The same bug silently disabled the Open-panel row highlight for those three. The assignment now sits just after `setBrand(...)` in each loader, with a comment saying why the position matters.
  - **The pending row lives in the RENDER function, not the fetch function.** `refresh*List` fetches the month and delegates to `renderQuoteListFiltered` / `renderDnList` / `renderInvListFiltered`, which is where the rows and the empty state are built - so that is where `window.pendingRowEl(kind, year, month, <unfiltered list>, key)` is called ([[05-FRONTEND-SHELL]]). Two rules: build it **before** the `!list.length` early-return (widened to `!list.length && !pendingRow`), and pass the **unfiltered** array (`qOpenAllQuotes` / `dnOpenAll` / `invOpenAll`), never the filtered `list` - the unfiltered one is what proves the duplicate has been saved and retires the provisional row. The row is deliberately rendered outside the type/client filters: it is the document you are working on and a chip must not hide it.
  - **`dirty = true` last is deliberate and sufficient.** `quoteState/dnState/invState.dirty` are `defineProperty` accessors whose setter calls `refresh*Saved()`, so the hooks' `refresh*Saved(); dirty = true;` order still lights the unsaved chip - the setter fires after. Don't "fix" the order by writing the private backing field.
- **Delivery/payment Workflow (2026-07-17):** PO/DN/INV expose saved-document context getters plus toolbar buttons `#btnPoWorkflow` / `#btnDnWorkflow` / `#btnInvWorkflow`. New documents keep the button disabled until Save enters edit mode. Clicking delegates to `window.openDocumentWorkflow(kind,no)`; PO passes `reloadPoFulfillment` so newly-linked rows/chips refresh immediately. Quotations intentionally have no Workflow button.

## static/quote.js

- **Unified document information row (2026-08-24):** the quotation, DN and invoice metadata bars (`#quoteMeta` / `#dnMeta` / `#invMeta`) share one non-wrapping grid with the PO strip - `doc-info-row` on the container, `doc-info-field` on each wrapper, `doc-info-control` on each input/select. Every control is 34px on a single baseline; each document declares one `minmax(px, fr)` track per field (QUT 6 / DN 7 / INV 8) and never re-wraps at narrow widths. Behaviour, IDs and JS are unchanged - these are layout hooks only. Contract: `tests/unified_document_info_row.test.js`; dimensions and the specificity gotchas live in [[08-STYLES-TEMPLATES]].
- **Internal Reference + panel card (2026-08-24):** `#qReference` participates in dirty state, `buildQuotePayload`, New/load/Duplicate lifecycle, and saved-document search. `renderQuoteListFiltered` delegates identity markup to `window.panelCardMainHTML`; the card no longer repeats the active MT/EQ/MP/SV type chip, while type filters remain unchanged.

**Purpose** - Quotation editor. Schema-driven for 4 quote types (materials/equipment/manpower/service), with terms editor, per-row image columns, an optional cost-entry column (IQD/USD), and a live grand-total.

**Key symbols**

Module / navigation

The ⚙ button snapshots the visible table columns (`quoteSettingsColumnsSnapshot`) into `window.openDocSettings("quotation", {subtype, columns, onSaved})`; `onSaved` only replaces the open document's columns when the settings columns editor reported `columnsChanged`, so layout-only settings saves preserve this document's own columns/widths.
- `showQuoteHub()` - lazy-loads types then `enterQuoteType(quoteState.type || "materials")`.
- `quoteRailItems()` / `quoteRailItemsBadged(activeKey)` - rail item list in `QTYPE_ORDER`, with unsaved-draft badge dots.
- `enterQuoteType(key)` - switch quote type; stashes old draft, resolves schema, seeds per-doc columns, builds thead, restores/inits doc, shows rail, calls `syncQuotePanelType()`.

Schema / columns (Phase T)
- `_cloneCols`, `_stockColumns`, `_nextQuoteColKey`, `editableColumns()`, `quoteSettingsColumnsSnapshot()` - per-doc column plumbing; `editableColumns` lazily seeds from the effective type schema, and the snapshot reads the live header inputs + resized widths for both type-settings and save payloads.
- `insertQuoteColAfter(afterKey)` / `deleteQuoteCol(key)` - add/remove a per-doc column; refuses to delete the schema `primary_key` or the last column.
- `quoteRenderColumns()` - `editableColumns()` plus a synthetic `cost` money column, **always appended LAST** (2026-07-24). Cost is NOT a schema column and never reaches the PDF.
- `_syncQuoteCostBtn()`, `setQuoteCostsToggle(on)`, `toggleQuoteCosts()` - the topbar **Cost** toggle that shows/hides the private cost-entry column.
- `buildQuoteThead()` - builds `#qThead`; renders editable header inputs + `+`/`×` controls, the synthetic COST header (with IQD/USD switch), wires header rename → `dirty`, calls `refreshColResizers()`.
- `quoteCurrencySwitchHTML(cur)`, `wireQuoteCurrencySwitch()`, `async setQuoteCostCurrency(next)` - IQD/USD cost switch; flipping converts already-typed cost cells at **this quote's deal peg** (`await api().doc_iqd_per_usd("quote", no)`; profile peg `window.IQD_PER_USD` for an unsaved quote).

New / number
- `initNewQuote()` - reset to a fresh materials-style quote; seeds columns from the effective type schema, terms from schema, date from `state.today`, and `autofitRows` from the quotation layout default.
- `populateClientList()` - fills `#qClientList` from `suggest_clients("")`.
- `refreshQuoteNumber()` - `get_next_quote_number(client, type)`; only overwrites `#qNo` if not `numberOverridden`.
- `quoteNew()` - `window.unsavedGuard.confirmNew("quote")` → `initNewQuote()`. The prompt and the rule behind it are shared by all four editors since 2026-10-01 ([[07-FRONTEND-SUPPORT]] ▸ static/unsaved_guard.js); quote.js registers itself with the guard right above `quoteNew`.

Rows / image cells
- `addQuoteRow(data)`, `insertQuoteRowAt(i)`, `buildQuoteRowTr(i)`, `wireQuoteRow(tr)`, `removeQuoteRow(i)`, `fullRenderQuoteRows()`, `focusFirstCol(i)`, `autoResizeTextarea(ta)`.
- `hasQuoteContent(row)` / `filledQuoteRows()` - a row counts as filled only if a value differs from its column `default`.
- Image column support: `_ensureImagePickerInput()`, `openImagePicker(row,col)`, `onImagePaste(e,row,col)`, `readFileToDataURL(file)`, `openCropper(dataUrl,row,col)` - single-click focuses the cell (so Ctrl+V pastes), double-click opens the file picker, drop accepts image files; crop uses Cropper.js and outputs `image/jpeg` at 0.85 quality capped at 900×700.

Autocomplete
- `onPrimaryInput(field,rowIdx)` → `suggest_quote_items(type, q)`; `showQuoteAc`/`hideQuoteAc`/`pickQuoteSuggestion(i)` - picking fills the whole row from Master Data and adds a trailing row. `priceFromMemory(...,"USD",quotePegSync())` maps `price_native` to Rate. **The cost fills in the CURRENCY IT WAS SAVED IN (2026-08-20)** - when the suggestion carries `cost_native`+`cost_native_ccy` the cell takes them verbatim (dinars stay dinars, the cell's own $/IQD toggle shows it); only older entries with no recorded currency fall back to `costFromMemory`'s conversion. Global keydown drives arrow/enter/escape navigation of `#acBox`.
- **The COST column header no longer carries a currency switch (2026-08-20).** `quoteCurrencySwitchHTML`/`dnCurrencySwitchHTML` are still defined but no longer rendered into the header - each cost cell has its own `.cost-ccy` `$`/`IQD` toggle (`app.js`), which is the one that matters now that a cost is stored per line in the currency it was typed in. Removed from ALL THREE editors (quote/DN/inv); the invoice`s separate FOOTER sell-currency switch (`invSellCurSwitch`) stays - that is the invoice`s own currency, not the cost toggle.

Terms
- `openTermsEditor()` - modal list editor; "Reset to default" reloads `quoteState.schema.terms`. `updateTermsCount()` writes `#qTermsCount`.

Totals / drafts
- `qmoney(v)`, `updateQuoteTotals()` - Total = `qty * rate` per row, grand only when `schema.grand_total`.
- `snapshotQuoteDraft()` / `restoreQuoteDraft(d)` + `stashQuoteDraftIfDirty(type)` / `discardQuoteDraft(type)` + `quoteDraftUnsaved{}` + `refreshQuoteSaved()` - per-type draft stash/restore for the rail, including `autofitRows`. Payload / save / open
- `buildQuotePayload()` - `{quote_no, date, quote_type, client_name, rfq_no, client_address, items: filledQuoteRows(), terms, columns, is_edit, signing_overlay, layout, col_widths}`. It refreshes `columns` from `quoteSettingsColumnsSnapshot()` so manual column drags persist in `doc_columns` when the quote is reopened; `layout.autofit_rows` persists the toolbar toggle per saved quote.
- `quoteRefreshSignChip()`, `quoteBulkInsert(objs, replace)`, `infoModal`, `validateQuote()` (client + RFQ + ≥1 item + **the pricing checks below**), `quotePreview()`, `quotePrint()`, `quoteSave(opts)`.
- **After the save is reported, `quoteSave` calls `window.quoteReviewNewItems(r.quote_no)`** (2026-09-10) - the mirror of what `savePO` does. A quotation is written in English, so it offers to complete the ARABIC half of any item the catalogue only knows in English; 82% of quoted items have none today, and every one is invisible to the Arabic PO that may follow. Awaited with its outcome ignored inside a `try`, and placed after every `return`-worthy failure: completing Master Data must never make a successful save look failed. One implementation shared with the PO's review - see `catalogueReview` in [[07-FRONTEND-SUPPORT]].
- **`quotePricingKeys()` / `quoteUnpricedRows()` / `quotePricingColumnsMissing()` (2026-08-14)** - the quotation half of the invoice rule ([[06-FRONTEND-EDITORS]] `invUnpricedRows`), and it differs in two ways that matter.
  - **Save remains available, PDF output does not.** A quotation is a working document: the client's request list is typed first and priced days later. Measured before shipping, a hard save block would have made **4 of 46** saved quotations unsaveable - including `QUT-MT-HDEC-031`, 169 items with quantities and no prices. Save offers **Save draft (no PDF)**; Preview and Print refuse until pricing is complete.
  - **The four types are not the same shape.** Materials is a priced table (`qty`/`rate`/`total`, `grand_total` on); Equipment, Manpower and Service are **rate cards** - no `qty`, no line total, `grand_total` off. `quotePricingKeys` asks the schema, so demanding a quantity never blocks an equipment quotation. It also intersects with the LIVE layout, so a table rebuilt with custom columns has nothing to check.
  - `quotePricingColumnsMissing` fires **only where a total is computed** (`grand_total`). On Materials, replacing Qty/Rate with `col_N` look-alikes silently yields a wrong grand total. Preview/Print refuse it; Save preserves it as an app-only draft with no PDF. On a rate card nothing computes, so the seven already-saved equipment quotations rebuilt that way (`QUT-EQ-HDEC-048` and friends) stay normally saveable. `quoteUnpricedRows` follows the same split: strict export, DB-only draft save. Pinned by `tests/quote_requires_price.test.js` and `tests/incomplete_price_save_backend.test.py`.
- Open browse: `quoteOpen()`, `syncQuotePanelType()`, `renderQuoteFilterChips()`, `renderQuoteListFiltered()`, `refreshQuoteList()`, `loadQuoteForEdit(quoteNo)`. Delete actions call `window.confirmAndDeleteDocument("quote", ...)` so Costing/To-Do and per-doc settings are cleared with the PDF.
  - **Typeless-family handling (Phase Y.3, universal):** a quote with **no `type_code`** (the Eshraqat single "Quotation" family - its `QT-####` filenames carry no MT/EQ/MP/SV segment) is **never hidden by the MT/EQ/MP/SV type filter**: the list predicate treats `!type_code` as always-pass, `renderQuoteFilterChips` **hides the type chip row** when no loaded quote has a type, and `syncQuotePanelType`/`refreshQuoteList` keep `qOpenTypeFilter="all"` in that case. Without this, saved Eshraqat quotes were invisible in the right panel because the filter pinned to the editor's `MT`. `inv.js` has the identical guard (`invTypeFilter`/`renderInvFilterChips`/`syncInvPanelType`/`refreshInvList`) - keep the two in sync. This is the only profile-specific frontend branch in these five files; everything else is backend-resolved data ([[13-PROFILES-BRANDS]]).
  - **The guard covers the open-panel lists ONLY, not the import dialogs.** In dn.js's import dialog a typeless quote passes the default "all" chip but is hidden if the user selects an MT/MP/SV type chip (no `!type_code` pass-through in its filter, ~line 1190), and its display type code defaults to `"QUT"`. inv.js's `openImportDialog` instead buckets typeless quotes under the Materials QUT source chip (`type_code || "MT"`).
- `_pushEmptyQuoteRow()` / `_wireQuoteGridPaste()` - grid-paste wiring. When cost entry is visible, it registers `quoteRenderColumns()` so the synthetic COST column can receive Excel-style Ctrl+V paste even though it is not part of the saved PDF schema.

**Reads / writes** - `quotes` + `quote_items` tables via bridge; `doc_cost_meta` via `set_cost_currency`/`get_cost_currency`. No direct file/disk access (the backend generator computes the save folder). Uses `localStorage` only indirectly via shared helpers.

**Calls / called by** - Bridge: `get_quote_defaults`, `get_quote_types`, `suggest_clients`, `suggest_quote_items`, `get_next_quote_number`, `check_quote_exists`, `preview_quote`, `save_quote`, `print_file`, `open_path`, `set_cost_currency`, `get_cost_currency`, `doc_iqd_per_usd` (per-deal peg for the cost-currency switch), `list_quotes_for_month`, `load_quote`, `reveal_in_folder`. Exposed to app.js/HTML via `window.initQuoteModule`, `window.enterQuoteType`, `window.quoteSave`, etc. `load_quote` is also called by dn.js/inv.js import flows, and by `quoteReviewNewItems` to read the saved rows back.

**Gotchas**
- **A document may only name a client that is ON FILE (2026-09-11).** All three save paths call `api._known_client_error` first and refuse an unknown, blank or archived client. Each editor then calls `window.ClientRequired.offer(r, kind)` ([[07-FRONTEND-SUPPORT]]); if it returns true the client was just added and the editor **saves again with a freshly built payload** - adding a client rewrites the client box to the printed legal name, so the first payload is stale. Work with no client uses the `N/A` client record, which prints a blank client line.
- **Every import applies the client's settings for what its source does NOT carry (2026-09-11).** `importDnIntoInv`, `importQuoteIntoInv` and `importQuoteIntoDN` call `ClientDefaults.adopt(kind, ["address"])`; the PO paths call `adopt(kind)` with nothing supplied. Skip it and the imported document silently keeps the profile's default receiving account instead of the client's.
- **Picking a client applies that client's saved settings (2026-09-06).** The client field's `change` handler is also the trigger for `static/client_defaults.js` ([[07-FRONTEND-SUPPORT]]), which fills the PRINTED CLIENT NAME (the client's legal name, from 2026-09-11), the address, and on an invoice the receiving account and tax status, and shows the client's short code as a chip in the field's label. It fills only blank or still-untouched fields, and **every path that replaces the document must call `window.ClientDefaults.reset(kind)`** so the values it wrote for the last document are not treated as replaceable on the next one. `initNew*` does it last; `load*ForEdit` / `restore*Draft` / `*MakeDuplicate` / `importQuoteInto*` / `importDnIntoInv` do it on entry. If you add another way to load a document into an editor, add the reset.
- **Autocomplete fills the COST too (2026-08-05)** - `pickQuoteSuggestion` always wrote the remembered cost into `quoteState.rows[i]`, but repainted the row through `editableColumns()`, which excludes the **synthetic** COST column. It is why `INV-MT-TDC-017` reports **97.6% margin on $4,233** and `INV-MT-TDC-018` **88.2%**. Both `pickInvSuggestion` and `createInvoiceFromDnAsLine` now write `""` and toast which DN it was; the reconcile is skipped when there is nothing to convert. - **tfoot colspan math** in `buildInvThead` assumes a specific column layout (NO + editable cols + del; Total is the rightmost editable column). Adding/removing columns of a different kind, or changing the trailing del cell, will visually misalign the tax/total rows. The COST toggle adds one body cell between the last editable column and the del cell, so both tfoot rows get a matching `qc-cost-col` pad cell - keep those in sync if you touch either. This is editor-only cosmetics - the PDF layout is computed separately by the backend generator ([[04-BACKEND-DOCGEN]]).
- **A column's `kind` is a FORMATTING hint, not a meaning.** `updateInvTotals` (and `updateQuoteTotals`) compute `row.qty * row.rate` **by key**. A column whose head reads "QTY" and whose kind is `num` is not the quantity unless its **key** is `qty` - new columns are keyed `col_2`, `col_3`, … (`_nextQuoteColKey`), so deleting the built-in Qty/Rate and adding look-alikes gives you the columns without the arithmetic, and every line totals zero. Renaming a heading is always safe: `col.head` changes, `col.key` does not. `invPricingColumnsMissing` blocks the save for invoices; **quotations have no such guard**, and 7 saved equipment quotations (`QUT-EQ-HDEC-048`, `-049`, `-027`, `-036`, `-038`, `-039`, `QUT-EQ-Gusan-026`) already carry hand-typed `col_N` totals that will not update when a rate is edited.
- **Only MATERIALS quotations do qty × rate at all.** `QUOTE_TYPES` gives equipment/manpower/service `grand_total: False` and no `qty` or `total` column - they are rate cards by design. Building a priced table there with custom columns is what leads to the trap above.
- Import is hidden for equipment/manpower types (`enterInvType`); the import dialog itself also drops EQ quotes. Two independent filters - keep them consistent.
- `withholding_pct` display defaults to `3.3` in three places (`initInvModule`, ⚙ `onSaved`, `loadInvForEdit`) using `?? 3.3`. The actual tax computation is backend; this is just the footer label.
- `amountInWords` here is the canonical copy; dn.js `dAmountInWords` is a manual duplicate.
- `restoreInvDraft` re-wires `#invSrcQuote` and repopulates quote suggestions - if the draft's client differs the suggestions are async and may lag one keystroke.
- `bankKey` falls back to `bankInfo[0].key` in the payload if unset; if `bank_info` is empty the payload sends `""`.
- Do not stash clean invoice states as type drafts. A saved/edit-mode invoice with custom columns must not be restored when the user switches away and later starts a fresh invoice of that type.
- Layout-only Invoice/DN/Quotation settings saves must not promote the open document's custom columns into type defaults; only an explicit settings-column edit should update defaults.

- `liftSection(name)` / `liftAll()` - moves the month/year controls, chip strips (wrapped with a Type/Client tag), and list into `.op-pane[data-section]`; splits pane into fixed header + scrollable list; hides the now-empty standalone Open view (`op-replaced`). Idempotent via `pane.dataset.lifted`.
- `_chipKindIcon(kind)` - inline SVG for the type/client chip-row tag.
- `showSection(name)` - activates a pane, sets title, resets search, adds `body.op-active`, triggers first-time `refresh`, highlights the open doc row.
- `hidePanel()` - hides the panel when no editor is visible.
- `triggerRefresh(name)` - resolves `window[refreshFnName]` at call time (load-order-independent) and calls it.
- `refreshActive()` - **debounced (120 ms)** refresh of the active section; exposed as `window.refreshOpenPanel` (editors call it after save/sign/new/delete; panel calls it on month/year change).
- `applySearchFilter(needle)` / `escapeHtml(s)` - client-side typeahead across `.po-row` cards in the active list; hides day separators while searching; shows a "No matches" empty state.
- `_currentOpenNo()` / `highlightActivePanelRow()` / `_onPanelRowClick(e)` + `_openDocNo` - Phase W open-doc highlight; reads `window.__currentEditorDoc` (set by each `loadXForEdit`) or the last-clicked row; flags `.po-row[data-edit=no]` with `.is-open`. The `.is-open` styling was **strengthened on 2026-10-01** (Waleed could not pick the row out): 20% tint instead of 9%, a 4px rail plus a full ring, and the OPEN pill, which is the non-colour cue - see [[08-STYLES-TEMPLATES]].
- `revealRow(no, tries)` (2026-10-01) - **scrolls the open document's row into view** inside `.op-pane-list`, centring it with `scrollTo` rather than `scrollIntoView` (which on a nested scroller also moves the page behind the panel), and re-applies the highlight. The month refresh that precedes it is async, so it polls up to 24 animation frames for the row and then gives up quietly - a row that never appears means the document is genuinely not in the month on screen. The MONTH half lives in app.js (`revealDocInPanel`, [[05-FRONTEND-SHELL]]) because the month selects belong to the editors.
- `activeEditor()` / `syncFromViews()` / `watchViews()` - MutationObserver on each editor view's `hidden` attribute drives show/hide.
- `wireUI()` - collapse/expand/refresh buttons, search input + clear + Escape, a MutationObserver that re-applies search + re-highlights after list re-renders, and month/year `change` → `refreshActive`.
- `init()` - resolves panel DOM, `liftAll()`, `wireUI()`, panel-level click highlight, `watchViews()`.
- `clearActivePanelRow()` (2026-10-01) - **`_openDocNo` was a latch.** It was set on every row click and never cleared, and because `_currentOpenNo()` falls back to it, it outlived the thing it stood for: pressing New sets `__currentEditorDoc = null` (the authoritative "nothing is open"), the fallback answered with the last row clicked, and the old document stayed highlighted beside a brand-new empty editor. The accessor in app.js now routes a **null** to this instead of to `markActive`, so the latch dies with it.
- `window.OpenPanel` - `{refresh, show, hide, section, markActive, clearActive, revealRow, focusSearch}`. `focusSearch()` is what the topbar Open buttons (`quoteOpen`/`dnOpen`/`invOpen`) call: uncollapse + refresh + focus search.

**Reads / writes** - `localStorage["openPanelCollapsed"]`. Reads `window.__currentEditorDoc`. No bridge calls of its own - it only invokes the editors' `refreshXList` functions by name.

**Calls / called by** - Calls `window.refreshPoList/refreshQuoteList/refreshDnList/refreshInvList` (resolved lazily by name). Called by every editor via `window.refreshOpenPanel()` and `window.OpenPanel.*`. Depends on shared list helpers (`panelDayKey`, `panelDaySepEl`, submit-button helpers) invoked from within each editor's render code, not here.

**Gotchas**
- **DOM relocation is destructive/idempotent**: `liftSection` moves live nodes (month/year/chips/list) out of the standalone Open views. Any code that queries those IDs still works, but code assuming they live inside `*OpenView` will break. `dataset.lifted` guards against double-lift.
- Section keys are `po/qut/dn/inv` but the quote editor's internal type key is `materials/...` and its code is `MT/...` - the panel section is `qut`, not `quote`. The refresh fn names in `SECTIONS` must exactly match the `window.*` names the editors expose (`refreshQuoteList`, not `refreshQut...`).
- Search is **pure client-side text match** over already-rendered `.po-row` text - it only filters the current month's loaded rows, never fetches. It hides day separators (`.panel-day-sep`) while a query is active.
- The active-section refresh is **debounced 120 ms**; a burst of `refreshOpenPanel()` calls (save→reset→re-init) collapses into one fetch - code that needs the list immediately after a mutation shouldn't rely on it having refreshed synchronously.
- Open-doc highlight spans the WHOLE panel (`.po-row[data-edit]` across all panes), relying on doc numbers being unique per type; only the active pane is visible so cross-pane collisions are cosmetically harmless but possible if numbers ever overlap.
- Month/year `change` auto-refresh only exists because those selects were lifted into the panel - the editors no longer own those events.
