# Frontend - Shell, View System & PO Editor

The pywebview SPA shell: the `api()` bridge, the boot sequence, the 20-view navigation system, the company-profile switcher, the Liquid-Glass dashboard, and the (Arabic) Purchase-Order editor + browse list.
**Covers:** static/app.js, templates/index.html

> Runtime context: this is a **pywebview** desktop app, not a web server. `templates/index.html` is loaded via `webview.create_window(url=index.html)`; there is no HTTP layer. All backend calls go through `window.pywebview.api` (see [[01-ARCHITECTURE]], [[02-BACKEND-CORE]]). The four doc types (PO / Quote / DN / INV) share this shell; sibling editor modules live in [[06-FRONTEND-EDITORS]] (quote.js / dn.js / inv.js) and the shared helpers in [[07-FRONTEND-SUPPORT]].

---

## static/app.js

**Purpose** - The SPA shell + PO editor. Owns the `api()` bridge helper, `bootstrap()`, the 20-view switch, the topbar status cluster, the type-rail sidebar, the company-profile switcher runtime (`initCompanyProfile`/`applyCompanyProfile`/`requestProfileSwitch` - see [[13-PROFILES-BRANDS]]), the dashboard (hubView) with Lottie/ApexCharts, the shared cross-editor helpers (autocomplete, arrow-nav, textarea auto-size, chip rows, modals, toast, import row-mapper), AND the full PO editor (`editorView`) + PO browse list (`openView`).

### Boot & bridge

- `api()` → `window.pywebview.api` - **every** backend call funnels through this. `api().save_po(...)` maps to `backend.api.Api.save_po(...)`.
- `bootstrap()` - the async boot chain, run on `pywebviewready`. `Promise.all([initToday(), initCompanyProfile(), loadUserPreferences()])` starts three independent reads together and awaits all of them **before** any UI binds. Then `bindUi()` → `populateOpenSelectors()` → `applyTheme(...,{persist:false})` → init the sibling modules (`window.initQuoteModule/initDnModule/initInvModule` from quote.js/dn.js/inv.js if present) → `applyCompactTables()` → `setupDocStatusSync()` → `showHub()` → `initThemeToggle()`. Optional animations start after the dashboard settles and paints. Wrapped in try/catch that toasts an Arabic boot-error.
- **The gate (2026-10-02).** `bootstrap()` calls `window.Gate.pageLoaded()` first, keeps `showHub()`'s return value (`hubPainted`, the dashboard-render promise - `showHub()` now RETURNS it), and after the try/catch runs `Promise.resolve(hubPainted).catch().then(Gate.ready)`: the launch card (2026-10-20; the doors before it) fades, and a switch gate opens, once the dashboard has drawn, or straight away if boot failed. `scheduleDashboardAnimations` still chains off the same promise. See [[07-FRONTEND-SUPPORT]] ▸ static/gate.js.
- `_startBoot()` - if the bridge object already exists (e.g. after F5), calls `bootstrap()` immediately; else waits for the one-shot `pywebviewready` event. Deferred to `DOMContentLoaded` so the sibling `init*Module` functions (parsed from later `<script>`s) exist before bootstrap calls them.
- `state` - the PO editor's module state object. Literal declaration is `{poNo, poDate, rows[], mode:"new"|"edit", editPoNo, dirtySinceSave, autofitRows, sourceQuote}`; `state.signingOverlay` is added at runtime (set by `resetEditor`, `loadForEdit`, and the `signingRegister` setter). `state.today` is a **live getter** (`Object.defineProperty`) returning `todayInfo()` on every read; the setter is a no-op so legacy `state.today = ...` assignments are harmless (prevents a stale date across midnight). `state.dirtySinceSave` is **also a `defineProperty` accessor**, not a plain field: its setter side-effects `refreshPoSavedState()` → `setUnsavedChip` + `setEditorSavedState`, so plain assignment keeps the topbar chips honest - never write the private backing field (`_poDirtySinceSave`) directly.
- `todayInfo()` → `{iso, display:"D/M/YYYY", year, month}` - client-side "today", matching backend `_format_date` (D/M/YYYY, **no** zero padding).
- `initToday()` - awaits `api().get_today()`, seeds `state.poDate` + the `#today` date input, and wires the input's `oninput` to keep `state.poDate` in D/M/YYYY.
- `_poInitialized` - module flag so the PO editor initializes its number/rows only on first entry per session.

### Navigation & view system

- `ALL_VIEWS` - the canonical array of all **17** view container IDs: `hubView, editorView, openView, settingsView, quoteHubView, quoteView, quoteOpenView, dnView, dnOpenView, invHubView, invView, invOpenView, dataManagerView, clientsView, analyticsView, costingView, lpoView, itemMasterView, todoView`.
  - **`lpoView` (2026-07-31)** joins the list - the Client LPOs screen, owned by `static/lpo.js` ([[07-FRONTEND-SUPPORT]]) and entered from the dashboard card `#dashOpenLpos` via `window.showLpos()`. **Rebuilt 2026-10-03:** `cl-header` (title, count, `#lpoSearch`, `#btnLpoNew`, `#btnLpoClose` Back), `.lpo-top` with `#lpoKpis` (three figures; Need action is the filter button `#lpoDueFilter`, made by lpo.js) and a `filter-chips-stack` of `#lpoKindChips` (type tabs) and `#lpoClientChips` (only with two or more clients), then `.lpo-body` with `#lpoList` (a table) and `.lpo-foot` (`#lpoTotals`, `#lpoReferenceReview`). `lpoDocView`'s header carries `#lpoDocActions` (next step, create actions, More) before `#btnLpoDocBack`; `#btnLpoDocPrev` / `#btnLpoDocNext` were removed.
- `hideAllViews()` - the pivot of navigation. Hides every view in `ALL_VIEWS`, hides `poStrip` + all four topbar action groups (`poActions/quoteActions/dnActions/invActions`), removes `body.on-dashboard`, calls `hideTypeRail()`, clears the editor-return breadcrumb (`clearEditorReturn`), hides `docStatus`, resets `window.__currentEditorDoc = null` + `setSubmittedChip(false)`, and clears `state.poFulfillment` + `setPoFulfillChips`. **Every** view-switcher calls this first, then un-hides its own view.
- `showHub()` - lands on `hubView`: hides all, un-hides hubView, hides Home button, adds `body.on-dashboard` (which hides the topbar), sets the brand **from the active profile** (`` `${profileDisplayName(id)} Documents` ``, fallback `"Business Hub"`), `refreshUniversalSettingsBtn()`, then `renderDashboard()` + `scheduleDashFit()` + `bindHeroLogoFlip()`. The dashboard promise catches failures and schedules `scheduleDashboardAnimations()` on settlement, including the failure path.
- `scheduleDashboardAnimations()` - two animation frames give dashboard data an opportunity to paint before `initCardLotties()`, `initLottieIcons()` and `initThemeLottie()` enqueue optional assets on the same profile-locked bridge as document data. Existing static SVGs remain until an animation mounts.
- `loadLottieData(slug)` / `_lottieDataRequests` - one promise per bundled animation, including concurrent requests from different buttons. Returns a fresh JSON copy for every host because Lottie mutates `animationData`. Invalid/failed requests are evicted for retry. These files are app-owned and shared by both profiles; this cache contains no document or company data. All three animation consumers use it. Guarded by `tests/startup_animation_priority.test.js` (behavioral scheduling, clone isolation and retry checks). Measurement and limits: [[15-STARTUP-AUDIT]].
- `showEditorView()` - the PO editor view (un-hides `editorView`, `poStrip`, `poActions`, Home).
- `showSettingsView()` - the universal settings view; loads `api().get_settings()`, populates the form, wires the sub-panel nav, About/Behaviour panels, and the header/closing/address editor.
- `showOpenView()` - **does not** switch to `openView` anymore; the right-side Open panel replaced it. Just calls `window.OpenPanel.focusSearch()` (fallback `refreshPoList()`).
- `enterPO()` - enters the PO editor; first-session init runs `initNextPoNumber()` + `addRow()` + `applyPoDateToday()`.
- `enterQuote()/enterDN()/enterINV()` - thin delegators to `window.showQuoteHub / enterDnEditor / showInvHub` (defined in the sibling editor modules). DN opens straight into its editor; the other two open mini-hubs.
- `setBrand(text)` - sets the topbar brand text.

### Company-profile switcher (multi-company: Abraj / Eshraqat)

The frontend half of the multi-company profile subsystem - full picture (backend `profiles.py`, brand assets, per-profile data roots) in [[13-PROFILES-BRANDS]]. Lives in app.js (~lines 900–1070); everything below is exposed on `window` (`applyCompanyProfile`, `initCompanyProfile`, `activeDirtyEditor`, `requestProfileSwitch`).

- `initCompanyProfile()` - awaited alongside today's date and preferences in `bootstrap()`, **before** `bindUi()`: `api().get_active_profile()` → `applyCompanyProfile(metadata)` + `initProfileSwitcher()`; toasts `metadata.warning` if the backend flagged one. A bridge failure here surfaces as the boot-error toast.
- `applyCompanyProfile(metadata)` - the single skinning function; anything profile-derived must flow through it. Sets module `_activeCompanyProfile`; `#dashProfileLabel` + `#dashHeroCompany` text (`ABRAJ|ESHRAQAT Business Hub` - asserted by `tests/company_profile_switcher.test.js`); the `--profile-accent` CSS var (fallback `#1F3864`); `data-profile` on `<html>` (the CSS skin hook); **`window.IQD_PER_USD`** (profile peg - Abraj 1400 / Eshraqat 1500); `#dashProfileLogo` + `#dashHeroLogo` `src` from `metadata.logo_data_uri` (a **data URI from the bridge**, not a static file - wrappers are hidden when there is no logo); and `aria-checked` on the `#dashProfileMenu` options.
- `profileDisplayName(profileId)` / `closeProfileMenu()` / `initProfileSwitcher()` - label helper + the dropdown wiring for the dashboard switcher DOM (`#dashProfileSwitcher`/`#dashProfileButton`/`#dashProfileMenu`, see index.html below).
- `activeDirtyEditor()` - one line since 2026-10-01: it returns `window.unsavedGuard.dirtyEditor()`, the shared registry every editor registers with ([[07-FRONTEND-SUPPORT]] ▸ static/unsaved_guard.js), as `{kind, key, save}`. It used to read the four dirty flags itself and ask about `dirty` **alone**, so switching company while a freshly opened document sat in an editor offered to save a document nobody had touched. The guard's rule is `dirty AND at least one filled row`. PO's registration sits directly below this function; quote/dn/inv register from their own files.
- `gateBrand(profileId)` (2026-10-02) - `{id, label, accent, logo}` for the gate's left door, from `_activeCompanyProfile.profiles` (each carries `brand_color` + `logo_data_uri`).
- `lockScreen()` (2026-10-02) - Ctrl+L (works while typing) and the dashboard's `#dashLockBtn`: `Gate.lock(gateBrand(active))`. Refuses with a toast while a Popup is open, because the popup's focus would stay live behind the doors. Listed in the `?` shortcut sheet.
- `requestProfileSwitch(profileId)` - **since 2026-10-02 the switch runs inside the gate**: `Gate.switchTo(gateBrand(old), gateBrand(new), () => api().switch_profile(id))` closes the doors in the old company's colours, changes brand while shut, and leaves them shut for the reload; a refused or failed switch opens them again and toasts as before. The guarded switch: if `activeDirtyEditor()` reports dirt, shows a Cancel / Discard / Save modal (overridable via the `window.profileSwitchPrompt` hook) **before** touching the bridge; then `api().switch_profile(profileId)` and, when the result says `reload`, **`window.location.reload()` - the whole SPA restarts**. All in-memory state is lost by design; nothing survives a profile switch except what the backend persisted.

### Submitted controls (right-panel doc cards)

- `submitBtnHTML(kind, docNo, submitted)`, `wireSubmitButtons(container, dataArray, keyField)`, `applySubmittedToButton(b, submitted)` - shared Submit/Submitted toggle used by PO/QUT/DN/INV open cards. Right-panel, To-Do preview/inline, and dashboard preview/inline Submit paths call it only after successful persistence and their own UI refresh; PO/QUT submits are unaffected.

No PDF` pill; a linked DN shows Linked; a linked paid invoice shows both Linked and Paid; PO Paid wins over Delivered; any submitted/linked/paid/delivered document suppresses the panel Signed badge. An opened editor still shows its real signing state in the top-right sign chip because the overlay is preserved.
- `panelCardMainHTML({no,date,reference,statuses,amount})` (2026-08-24) - shared compact identity block for PO/QUT/DN/INV right-panel cards: number left, existing list date and optional invoice amount right, optional one-line internal Reference below (escaped text plus escaped full-value `title`), then status pills. Only `statuses` is trusted markup from `panelStatusHTML`; every persisted value is escaped.

### Shared suggestion constants

- **`ITEM_META_KEYS` (2026-08-16; Master Data money 2026-08-20)** - `window.ITEM_META_KEYS`, defined in `app.js` beside `window.ICON` and used by `quote.js` / `dn.js` / `inv.js`, which are separate classic scripts sharing global scope. It lists payload keys that describe or store the **item** rather than directly supply a document column: paired names, `img_query`, `item_no`, `cost_usd`, and both canonical native money/currency pairs. Each editor has TWO loops over the payload - one builds the grey subtitle, one applies a picked suggestion to the row - and **both** must skip these. Price and cost are then applied explicitly through `priceFromMemory` / `costFromMemory`, which converts them into that document's Rate/Cost currency. Filtering only the display would still let internal keys become phantom fields in `rows_json`. Pinned by `tests/suggestion_subtitle_keys.test.js` and `tests/quote_autofill_master_money.test.js`.

### Dashboard (hubView) - dynamic content

- **Hero greeting - `DASH_GREETINGS` / `DASH_TAGLINES` / `renderHeroGreeting(now)` (2026-08-04).** The hero used to be a hard-coded `h < 12 ? "Good morning" : …` ternary plus one fixed subtitle. It now picks **one pair per app start**, chatbot style: 74 greetings across `morning / afternoon / evening / night / any` (the hour's bucket is concatenated with `any`, so ~36 candidates per render) and 40 taglines. `dashGreetingBucket(hour)` splits at **5 / 12 / 17 / 22**. `pickFreshLine(pool, memory, keep)` holds the last 6 greetings and 12 taglines so a new run never repeats the line you just read.
  - **One line per app start, not per hub entry (Waleed's ruling, 2026-10-01).** It used to re-pick on every `showHub()`, so stepping into a document and coming back changed the greeting, which read as a glitch. `pickHeroPair(now)` does the choosing and `renderHeroGreeting` calls it **only when `_dashHeroPick` is null**, then re-renders the same pair forever. Anything that wants a new line must null `_dashHeroPick` (nothing does; a profile switch reloads the SPA, which is a new run). `tests/dash_hero_greeting.test.js` section 7 asserts both halves: the line is stable across 50 hub entries even across a time-bucket boundary, and a fresh run never hands back the previous line.
  - **`{name}` is a slot, not a suffix.** `renderHeroGreeting` splits the chosen line on `{name}` and writes the three pieces into `#dashGreeting` / `#dashUser` / `#dashGreetingTail`, so a line can put the name anywhere (`"{name}, good morning"`, `"Still going, {name}? Let's be quick"`). A line with no `{name}` renders whole, with the other two spans blank. The name itself is read **once** from `#dashUser`'s initial markup and cached in `_dashUserName` - it is the only place the user's name is written down.
  - **Length is a real constraint, not a style note.** `.dash-view .dash-hero` is a **fixed height with `overflow: hidden`**, so a greeting long enough to wrap pushes the date row out of sight. Measured in headless Chrome at 1024×600 / 1366×768 / 1920×1080: the widest greeting (42 chars) takes **65 %** of the available width in the worst case and the widest tagline (67 chars) 58 %, putting the overflow point near 64 and 115 chars. `tests/dash_hero_greeting.test.js` caps them at 52 / 90. The `nowrap` + `text-overflow: ellipsis` on `.dash-hero h1` and `.dash-hero .dash-user` (plus **`min-width: 0`** on the flex child `.dash-hero-content`, without which the ellipsis never engages) is the backstop, not the plan - see [[08-STYLES-TEMPLATES]].
  - **Taglines are statements, never questions.** A greeting may be a question, so a question tagline directly underneath reads as a double-ask. The test enforces it because nothing in the code shows the rule.
  - **No tagline claims anything about the data** ("all caught up", "everything's in order") - `renderHeroGreeting` runs *before* any bridge call, so it has not looked at a single document.
- **`renderDashboard(opts)` keeps what is current (2026-10-01).** Waleed: going back to the hub meant ~2 s of loading every time. It now asks `api().dashboard_state_token()` FIRST ([[02-BACKEND-CORE]]); when the token equals `_dashShownToken` (the data on screen) it re-fits the layout and returns - **no data calls, no redraw**. When it differs it fetches as below, but **paints skeletons only when nothing is drawn yet** (`_dashShownToken == null`), so a refresh swaps in place with no blank flash; and `_dashDrawn` holds a JSON signature per section (`attention` / `bid` / `stats`) so a section whose numbers are identical is not redrawn (no replayed donut animation or count-ups; the slider keeps its slide and just resumes). The token is read BEFORE fetching and remembered only when **every** section succeeded - a write that lands mid-fetch costs one extra fetch next time and can never be hidden; a failed section (`renderDashboardError` also nulls the token) makes the next visit fetch. Retry passes `{force: true}`. The Insights slider's 7 s tick now returns early while `#hubView` is hidden - the timer survives trips to an editor because the hub is no longer rebuilt. Pinned by `tests/dashboard_keeps_current_view.test.js` (runs the real function against a fake bridge and counts calls).
- `renderDashboard()` - the async landing renderer. It paints stable loading states immediately, then starts all five month lists, analytics, costing, and Needs Attention concurrently. Needs Attention renders independently, so a slow analytics or costing call cannot hold it blank. Bridge calls use a bounded timeout with one retry, section-level recovery UI, and a render-sequence guard so stale responses cannot overwrite a newer dashboard. Current-month lists are reused for search; only the previous month is fetched in the background. `showHub()` catches top-level render failures.
- `renderBidDonut(segs, winRate)` - the interactive ApexCharts "Insights" donut (Won/Open/Lost), themed from CSS tokens; the legend rows are real buttons, hover previews an outcome, click pins/unpins it, and the ring + legend share the same selected state. `_bidDonut`, `_bidDonutData` cached for re-theming. **Clears `host.innerHTML` before mounting the chart (2026-07-22)** - ApexCharts *appends* into the host without removing existing children, so the `.dash-skeleton-ring` loading placeholder set by `renderDashboardLoading` stayed drawn on top of the donut until the first hover (whose `updateOptions()` rebuilt the host and incidentally wiped it). That was the "stuck loading spinner that only goes away when you hover the donut" bug; the zero-data branch already cleared the host, the normal path did not.
- Slider: `renderStatsSlider(pages)`, `buildSlideHTML/buildDonutHTML/buildMiniVBarsHTML/buildMiniHBarsHTML/buildMiniAreaHTML`, `goToSlide/activateSlide/restartAutoAdvance` (7 s auto-advance), `animateCount` (count-up), `dashMoneyShort` ($12.4k/$1.2M). `DASH_DONUT_R=46`, `DASH_DONUT_C=2πR`.
- `forceInsightsPaint()` - called at the end of `renderDashboard` after the charts render. Nudges a repaint of `.dash-mid-side` (opacity flip + `translateZ(0)` layer bump, once now + once at 400 ms) as a secondary guard against WebView2 compositing lag on freshly-injected chart content. Visually a no-op. (The actual spinner bug was the uncleared skeleton ring - see `renderBidDonut`.)
- `fitInsightsCard()` / `scheduleInsightsFit()` - keeps the "By Document Type" slider card (`.dash-stats-card`) usable on a short Insights column. Measures the card's own `getBoundingClientRect().height` and toggles `.stats-tight` below `INSIGHTS_TIGHT_PX` (240), which trims its chrome so the chart body keeps usable height ([[08-STYLES-TEMPLATES]]); the slide bodies themselves scale via CSS caps. Safe from feedback loops because the card is `flex: 1 1 auto` - its height comes from the column, not its content, so the class can't change what is measured. `scheduleInsightsFit` re-measures at rAF + 300 ms + 900 ms because the Bid-outcomes chart renders async; a `resize` listener keeps laptop↔monitor live. **Gotcha:** never measure this with `offsetTop` - `.dash-donut-card`'s `offsetParent` is `.dash-inner`/`.dash-view` (position:relative), not `.dash-mid-side`, and mixing it with `side.clientHeight` compares two different origins (that bug once hid the card on every screen).
- `fitOneToolbar(el)` / `fitActiveToolbar()` - keep the editor topbar action groups to **one row at every width** (see [[08-STYLES-TEMPLATES]] for the `.tb-compact`/`.tb-icons` tiers + `data-short`). Measures `scrollWidth` vs `clientWidth`, stepping full → compact → icons. Wired once (IIFE `setupToolbarFit`) via a MutationObserver on each group's `hidden` attribute + a debounced window-resize; deliberately not a ResizeObserver (would loop on the class change).
- **Dashboard mid row redesign (2026-10-21, Waleed).** Needs attention has the WHOLE left column; each card (`naCard` in `renderNeedsAttention`, class `.is-compact`) is **one line** - icon, number, status tag, action. The client · date line went (the button says what the document needs; one line per card shows 16 instead of 8 on a 1080p screen); both stay in the card's hover `title`. A bid's countdown rides in its tag ("Decide · 3d left", "Decide · today" + `.is-urgent`). `RENDER_CAP` 24 -> 40 for the taller column. Card order is decide, uncosted, unsubmitted, deliver, **unpaid last** (2026-10-21: unpaid invoices wait weeks on the client and were filling the grid ahead of work that can be done today; the To-Do view follows the same rule). **Search results keep their client · date line** (that is how you recognise a hit). Insights is ONE card `#dashInsightsCard` holding `#dashDonutCard` and `.dash-stats-card` as panels (neither is `.glass` any more; every id the JS uses is unchanged), and Quick access (`.dash-bottom`) moved under it in the RIGHT column. Pinned by `tests/dash_mid_row_layout.test.js`.
- **Short screens (2026-10-21/22, Waleed's laptop = 1536x801 at 125%).** The dashboard fills one screen and nothing had a floor, so "By Document Type" got 94px. Now: the hero and the four Create New tiles keep their size (his ask); at 960px tall and below the bid-outcomes donut drops 188 -> 136px and Quick access slims and loses its heading; the mid row has a 400px floor (~20px under the laptop's ~419px so DPI rounding cannot tip it); below that `.dash-inner` scrolls. The donut height is CSS (`--dash-donut-h` on `#dashBidDonut`) read by `renderBidDonut` through `_bidDonutDrawnAt(host)`, which records `_bidDonutDrawn = {h, w}`; `scheduleDonutRefit()` (on `resize` AND on the `(max-height: 960px)` media query's `change`) waits 180ms for the column to settle, then redraws only if the height or width changed - redrawing on the media-query change itself drew it for the old width. A document can be costed in one currency and billed in another, so the two must not share a rate. Quote and DN pass USD; invoice passes its selected sell currency. All three primary-column pickers use this helper, so a Master Data `price_native` becomes the visible Rate rather than a hidden `price_native` row property.
- **`costFromMemory(data, docCcy, peg)` (2026-08-13)** - the cost an autofilled item should put in a row, in THIS document's unit. Handed over VERBATIM when the catalog's unit already matches (no rate involved, nothing to be wrong about); otherwise converted at `peg`, which every caller passes as the DOCUMENT's rate (`quotePegSync`/`dnPegSync`/`invPegSync` → the rate pinned under the table, else `doc_iqd_per_usd`, which applies the cash rule). Falls back to `cost_usd` for entries written by a document save; a raw `cost` with no recorded currency is still never replayed. Shared by all three pickers so they cannot drift. Alongside `rowCostCellHTML` / `toggleRowCostCurrency` / `convertRowsToCostCurrency` / `rowCostCurrency`.
- **Live cost / sell / profit / margin cards (2026-08-04)** - `docUnitEcon(row)`, `docLineEcon(row, opts)`, `computeDocEcon(spec)`, `renderEconCards(host, econ, opts)` (+ `_econNum`/`_econCost`/`_econToUsd`/`_econMoney`), all on `window`. Painted under the Quotation / DN / Invoice footers into `#qEconCards` / `#dnEconCards` / `#invEconCards`, live from each editor's `update*Totals()`. **Frontend only - no bridge method, no restart.**
  - **These are a deliberate PORT of `database._detect_unit_econ` + `_line_econ`, not a reimplementation.** Two figures both claiming to be "the profit on this document" that disagree are worse than showing none - and the cheap one is on screen far more often. `tests/doc_econ_parity.test.py` runs 27 shared fixtures through **both** implementations and fails on any divergence, including the `auto` guess flag. Change one, change the other, and add a fixture.
  - **`cost` is PER UNIT.** `line_cost = qty * cost`. Summing the COST column - the obvious implementation - understates every line with qty > 1.
  - **Three currencies can be in play at once.** Costs are entered in USD or IQD (converted at the document's deal peg); an invoice may additionally *sell* in IQD, at its own recorded rate ([[06-FRONTEND-EDITORS]]). A `cost_sell` override is **always** USD - it is typed on the costing screen - so it must not be converted again.
  - **Extra costs count.** Document-level costs live in `extra_costs_json` and are already returned by `load_quote`/`load_dn`/`load_inv`; omitting them overstates profit on every document that has them.
  - **The uncosted warning is not optional.** A profit computed from half-costed rows is an upper bound that looks exactly as authoritative in a card. `computeDocEcon` returns `billable`/`uncosted`/`costed` (matching the backend's `costed` flag) and `renderEconCards` shows "N of M lines not costed - $X of the cost is estimated". **Since 2026-10-21 an uncosted billable line is no longer free:** `docLineEcon` costs it at `uncostedMarkup()` (`window.UNCOSTED_MARKUP` from profile metadata, fallback 0.40) exactly as `database._line_econ` does, and returns `estCost`; `computeDocEcon` sums it as `estCost`. The line's `state` stays "unknown" and it is never judged a loss.
  - **Profit vs loss is never red/green** - the card's LABEL changes ("Profit"/"Loss"), a loss is red, a profit stays neutral ([[08-STYLES-TEMPLATES]]). Pinned by `tests/econ_cards_render.test.js`.
- **Per-item profit and loss (2026-08-25)** - `computeDocEcon` now also returns **`lines`** (every row's own economics, index-aligned) plus **`losers` / `lossTotal` / `lossCount`**; `docLineEcon` returns `name` + `unitCost`; `renderEconCards` paints `_econLossHTML(econ)` under the cards. New `window` helpers: **`rowProfitCellHTML()`** (the read-only PROFIT cell, beside `rowCostCellHTML`), **`paintRowEconCells(tbodyId, econ)`** (fills that cell + marks the row), and **`focusEditorRow(tbodyId, index)`** (the loss list's click target - scroll, flash, focus the cost cell). Constants `LOSS_EPSILON = 0.005`, `ECON_LOSS_SHOWN = 5`. Still frontend-only: no bridge method, no restart. Pinned by `tests/line_profit_and_loss.test.js`.
  - **The Profit card cannot answer "which line".** A document is routinely well in profit with several lines under cost - the winners hide the losers, and nobody divides twenty costs by twenty sells by hand. That is the whole feature.
  - **Only a BILLABLE line with a REAL cost is judged.** An uncosted line has an *unknown* cost, not a zero one; calling it "not a loss" would be the same confident wrong number the uncosted warning exists to prevent. The two markers coexist deliberately.
  - **A cent of tolerance (`LOSS_EPSILON`).** Converting a dinar cost lands a break-even line a hundredth of a cent under; flagging that teaches the user to ignore the marker. A genuine 2-cent loss is still reported.
  - **Everything is USD, after both conversions** - an IQD cost against a dollar sell is wrong by the peg (~1400x) and would report every line as a catastrophe; an IQD-billed invoice must convert its sell side too. The figures come from `docLineEcon`, so this cannot drift from the backend.
  - **`loss` is the POSITIVE size of the hole**, so no caller can render `--$84`. Sorted worst first; at most `ECON_LOSS_SHOWN` are listed and the remainder is counted ("+3 more lines below cost") rather than silently dropped.
  - **Every entry names the item AND shows sell vs cost per unit.** "You are losing $84" is not actionable without knowing which of the two numbers to move. A row with no name falls back to "Line N".
  - **`lines[i].state` is a FOUR-way answer, not a number**: `profit` / `loss` / `unknown` (billable but uncosted) / `blank` (an empty row). The PROFIT column paints from it, which is why an uncosted line reads "-" and never "$0.00" - unknown and zero are different things, and only one of them is a fact.
  - **PROFIT is COMPUTED and read-only.** It has no `data-k` and is never a row key, so unlike `cost` (which IS stored, privately, in `rows_json`) it cannot reach a payload or a PDF. Its column carries `_readonly: true` so `grid_paste.writableColumns` drops it, and `kind: "profit"` rather than `"computed"` because the row builders' first branch claims `"computed"` for the document's own Total column.
  - **The strip is COST + PROFIT together** (`.qc-private`), never in a column the client sees - both are derived from the cost and equally private ([[08-STYLES-TEMPLATES]]).
  - **Words, not colour** - heading "N lines sell below cost", the cell reads `LOSS -$84.00`, and a healthy line stays neutral ([[waleed-colour-blind]]).

**Gotchas**
- **Script load order is load-bearing.** `signing.js` + `bulk_paste.js` MUST load before app.js (their top-level `if (window.signingRegister)` / `if (window.bulkPasteRegister)` checks must succeed at app.js eval). `grid_paste.js` loads AFTER app.js, so `_wirePoGridPaste()` is deferred until `window.setupGridPaste` exists. `todo.js` + `po_link.js` load between analytics.js and col_resize.js - their globals (`window.showTodo`, `openTodoDocModal`, `openPoSourcePicker`, `openPoFulfillPicker`) are only guarded by `if (window.X)` checks at call time. `open_panel.js` loads LAST so every `refresh*List` is already on `window`. An inline `<script>` block near the end of index.html (just before open_panel.js) re-exports the five `refresh*List` functions to `window` explicitly.
- **`bootstrap()` calls `window.initQuoteModule/...` which are defined in later scripts** - this only works because `_startBoot` defers to `DOMContentLoaded`. Reorder at your peril.
- **`state.today` is a getter** - never cache it. Assigning to it is a deliberate no-op. Editors that read `state.today` on "new" always get the live date; the PO editor instead reads the `#today` input.
- **`state.dirtySinceSave` assignment triggers chip updates** (setter → `refreshPoSavedState` → `setUnsavedChip`/`setEditorSavedState`). Don't bypass it by writing the private `_poDirtySinceSave` - the topbar chips will go stale.
- **`switch_profile` reloads the entire SPA** (`window.location.reload()`) - all in-memory state is lost by design. The `activeDirtyEditor()` guard must run **before** `api().switch_profile`. Anything caching profile-derived values (`window.IQD_PER_USD`, `--profile-accent`, `data-profile`, logos, hero text) must be set inside `applyCompanyProfile` so a switch can never leave half-skinned UI. See [[13-PROFILES-BRANDS]].
- **Date format mismatch:** backend wants **D/M/YYYY with no zero-padding**; `<input type=date>` uses ISO. Always round-trip through `displayToIso`/`isoToDisplay`. `todayInfo().display` must stay in sync with backend `_format_date`.
- **A PO is ONE document over N pages** (2026-07-29 - it used to split into multiple sub-POs). `save_po` still returns `r.saved[]` for contract stability but it always holds exactly one entry, and `savePO` already only used `r.saved[0]`. `update_po` returns a single `r.path`. `updateSplitWarning` calls `po_page_count` on every keystroke path - the page-break rule is content-height based in the backend, so it's always an API round-trip, not a local guess.
- **Edit vs Export reset:** `savePO({stay:true})` keeps the editor (and flips to edit mode on the first sub-PO); `savePO()`/Export resets to a fresh PO after running `poAfterExport`. Editing an existing PO and then Export still resets (Phase L.4.5).
- **`hideAllViews()` is the single source of truth** for tearing down a view. Anything a view shows (rail, status cluster, back button, action group, `__currentEditorDoc`) is reset here; the entering view must re-show what it needs. Adding a new view means adding its ID to `ALL_VIEWS` **and** ensuring it un-hides its own action group / status.
- **`__currentEditorDoc` has a side-effecting setter** - assigning it re-highlights the Open panel. Setting it to `null` is meaningful (clears the highlight); don't skip that on navigation.
- **A loader must assign `__currentEditorDoc` AFTER its `hideAllViews()`, never before (fixed 2026-08-04).** `hideAllViews()` nulls it, and `showEditorView()` calls `hideAllViews()` internally - so an assignment placed earlier in the function is wiped before the loader returns. This shipped broken in all three English loaders (`loadQuoteForEdit`, `loadDnForEdit`, `loadInvForEdit`); only `loadForEdit` worked, because PO assigns it a **second** time after `showEditorView()`. Two symptoms, one cause: the Open-panel row never highlighted for those three, and **Duplicate silently did nothing** - `duplicateDocument` reads the value back to confirm the source loaded, so the guard failed and it returned `false` after merely opening the original for editing. Pinned by `tests/duplicate_document.test.js` §8, which strips comments before checking the order (the explanatory comment above each assignment names `hideAllViews()` and would otherwise satisfy the check on its own).
- **`SUGGEST_ON_NON_PRIMARY = false`** silently disables the universal autocomplete dropdown for every non-primary column across the whole app (column-memory writes continue). If autocomplete "stopped working" on a secondary column, this constant is why.
- **Row auto-append logic** lives in two places (`wireRow`'s input handler and `pickSuggestion`) - both append a trailing blank when the last row gains content. `poBulkInsert`/`_wirePoGridPaste` also maintain the trailing blank. Keep them consistent or you get duplicate/missing blank rows.
- **The PO editor's item table is RTL** but carries inline `style="width:X%"` + `data-col-key` on each `<th>` so the shared `readEditorColWidths` works the same as the LTR QUT/INV/DN tables.
- **`safe()` and `poAfterExport()` toast in Arabic**; the English editors use `afterExportPdf`. Don't cross the wires - the PO section is intentionally Arabic-only chrome.
- **The USD peg is never hardcoded client-side.** `applyCompanyProfile` publishes the PROFILE peg as **`window.IQD_PER_USD`** (from `get_active_profile().iqd_per_usd`; Abraj 1400 / Eshraqat 1500) - used only as a fallback. Anything converting a real stored cost must ask the backend for the **deal** peg via `api().doc_iqd_per_usd(kind, doc_no)` (cash deals settle at 1500), or read `iqd_per_usd` off the costing payload. See [[03-BACKEND-DATA]] `doc_iqd_per_usd`.

**Gotchas**
- **Script order is a hard contract** (see app.js gotchas). Moving a `<script>` breaks the register-on-load pattern (`signingRegister`/`bulkPasteRegister`) or leaves `setupGridPaste`/`refresh*List`/`init*Module` undefined at bind time.

- **The standalone `*OpenView` pages are structurally live but visually dead** - `open_panel.js` relocates their inner controls into `#openPanel`'s panes at boot. The render functions (`refreshPoList`, etc.) still target the original element IDs, now living inside the panel. Deleting an `*OpenView` shell would break the panel wiring.
- **Every action group and its buttons exist in the DOM simultaneously** and are shown/hidden by `hidden`; the four `⚙` settings SVGs and Save/Export/Sign/Preview/Print icons are duplicated per doc type. IDs are the only disambiguator - keep the `btnPo*/btnQ*/btnDn*/btnInv*` prefixes consistent, since `LICON_MAP` and the keyboard-shortcut router select by those IDs.
- **`#poStrip` is separate from `#editorView`** - both must be un-hidden together (see `showEditorView`/`enterPO`). Un-hiding only one shows a headerless or strip-less editor.
- **First-paint theme script must stay inline in `<head>`** and run before the stylesheets take effect - moving it into app.js reintroduces the dark-mode flash. It intentionally reads only the cached `localStorage.abraj_theme`; the authoritative saved value is `data/settings.json.preferences.theme`.
- **`<html>` is RTL**; English views (`dashboard`, quote/dn/inv, settings, data manager, clients, analytics, costing, and the Open panel) each set `dir="ltr"` locally. The PO editor + its strip + `openView` inherit RTL. The arrow-key cell-nav in app.js reads this direction - a view with the wrong `dir` will navigate cells backwards.
