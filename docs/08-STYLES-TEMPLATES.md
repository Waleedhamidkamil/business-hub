# 08 - Styles & Print Templates

Coarse map of the CSS design system, the two print skins (six print stylesheets), the Jinja PDF page templates, and the vendored front-end libraries.

**Covers:** static/app_styles.css, static/po_styles.css, static/quote_styles.css, static/dn_styles.css, static/inv_styles.css, static/eshraqat_print.css, static/costing_styles.css, static/dark.css, templates/po_page.html, templates/quote_page.html, templates/dn_page.html, templates/inv_page.html, templates/eshraqat/*_page.html, templates/eshraqat/_components.html, static/lib/apexcharts.min.js, static/lib/lottie.min.js, static/cropper.min.js, static/cropper.min.css

Two distinct worlds live here:
1. **App UI CSS** (`app_styles.css`, `costing_styles.css`, `dark.css`) - styles the pywebview window / `templates/index.html` front end (the 20 views in `app.js`). See [[01-ARCHITECTURE]], [[05-FRONTEND-SHELL]].
2. **Print CSS + Jinja templates** - the A4 PDF documents produced by the generators in `backend/`. The print world has **TWO skins**:
   - **Default (abraj) skin** - `po/quote/dn/inv_styles.css` + `templates/*_page.html`, one stylesheet+template pair per doc type.
   - **Eshraqat skin** - one shared `static/eshraqat_print.css` + `templates/eshraqat/{po,quote,dn,inv}_page.html` + macro library `templates/eshraqat/_components.html`, used for ALL four doc types when `config.ACTIVE_PROFILE == "eshraqat"`. See the dedicated section below and [[13-PROFILES-BRANDS]].

   The profile branch lives ONLY in the generators (`backend/{pdf,quote,dn,inv}_generator.py` pick template name + `css_text`/`css_href` by `ACTIVE_PROFILE`); the four base templates contain NO profile conditionals, and the default path is byte-identical to what this doc describes. See [[04-BACKEND-DOCGEN]].

> **⚠️ Skin split (most important fact in this doc):** editing `po/quote/dn/inv_styles.css` or the base `*_page.html` has **ZERO effect when `ACTIVE_PROFILE == "eshraqat"`**, and vice versa. Every print-layout change must be checked in BOTH skins - or consciously skipped in one.

## Shared print conventions (applies to all print CSS + templates, both skins unless noted)

Rather than repeat the same blocks under every file, the invariants shared across ALL five doc types are collected here. **Changing any of these silently affects all five documents.**

- **`@page { size: A4; margin: … }`** - base skin: PO uses `10mm`, quote/dn/inv use `12mm`. The `.*-page` element's `width`/`min-height` are hand-computed as `A4 dimension − 2×margin` (PO `190mm`/`277mm`; quote/dn/inv `186mm`/`273mm`). Eshraqat skin: `@page` margin `8.8mm 8.75mm 15.9mm`, `.esh-page` `192.5mm` × min-height `270mm` - the min-height is **deliberately ~2mm short** of the 272.3mm printable height so the absolute page number doesn't spill onto a blank second page (comment in the file). **These are hand-computed pairs in all FIVE print stylesheets - if you change the `@page` margin you MUST change the page-box width/height to match** or the layout drifts off the printable area.
- **Signature/stamp overlay block (`.sig-box`, `.sig-overlay`, `.sig-stamp`, `.sig-hand`)** - an IDENTICAL "Phase K.1" block is duplicated verbatim at the bottom of all five base stylesheets, and a SIXTH variant lives in `eshraqat_print.css` (~line 222). `.sig-box{position:relative}` makes each signature box the positioning context; `.sig-overlay` is absolutely pinned to its bottom; `.sig-stamp` (z-index 2, opacity .95) and `.sig-hand` (z-index 3) share `transform-origin: 50% 100%`. The generator injects an inline-styled overlay HTML fragment via `{{ sig_overlay_* | safe }}`, each with a random translate/rotate baked in. **A fix here must be pasted into all SIX files.**
- **`.page-number`** - identical "Phase L.4" block in the five base stylesheets: `position:absolute; bottom:0; left:5mm; 7.5pt; #999`. Template emits `Page {{ page.page_index }} of {{ page.total_pages }}`. The eshraqat skin uses a DIFFERENT class, **`.esh-page-number`**, emitted by the `_components.html` `page_number()` macro.
- **`--autofit` table variant** - every table has an `--autofit` modifier class (`items-table--autofit`, `q-table--autofit`, eshraqat's `esh-table--autofit`, etc.) that drops fixed row heights so rows hug their text (`height:auto`, tighter `line-height`). Toggled by the generator's `autofit` flag in the template: `class="… {% if autofit %}…--autofit{% endif %}"`.
- **`white-space: pre-wrap` on table cells** - deliberate, so newlines the user typed into editor cells survive into the PDF. Removing it collapses multi-line cell content.
- **`table-layout: fixed` + per-column `width`** - all item tables are fixed-layout; column widths come either from hard-coded classes (PO base skin) or inline `style="width: {{ c.width }}%"` from the generator's column schema (base templates AND the eshraqat `table_header` macro). **Column width math must sum to ~100%**, and grand-total/tax `colspan`s are computed in Python - schema changes require generator span updates.
- **Per-page row height via CSS variable** - quote/dn/inv set `--q-row-mm` / `--dn-row-mm` / `--i-row-mm` inline per page (Phase L.3). The pagination engine (`build_layout` in each generator) computes this in mm so few-item pages stretch and dense pages pack. Defaults: quote/dn `12mm`, inv `14mm`. `fill_table` sets an explicit table `height` so tbody rows absorb slack while thead/tfoot stay fixed. The eshraqat skin's equivalent is **`--esh-row-mm`** (defaults: quote 11mm, dn 8mm, inv 14mm, PO via `table_row_mm`).
- **CSS injection mode** - the template head reads: `{% if inline_css %}<style>{{ css_text|safe }}</style>{% else %}<link href="{{ css_href }}">{% endif %}` - present in all 4 base AND all 4 eshraqat templates. Generators pass `inline_css=True` for the actual PDF (Chromium print) and link mode for in-app HTML preview. `css_text` comes from each generator module (`backend/{pdf,quote,dn,inv}_generator.py`), which picks the base file or `eshraqat_print.css` by `ACTIVE_PROFILE`. `css_href` base skin: `../static/<type>_styles.css`. Eshraqat: `../static/eshraqat_print.css` in pdf/dn/inv generators but `../../static/eshraqat_print.css` in `quote_generator.py` (~line 650) - **the relative depths intentionally differ per generator's preview location; don't "normalize" them.**
- **Fonts are `@font-face`-free in print CSS** - print stylesheets rely on OS fonts installed on the Windows host. Base skin: Arial/Tahoma for PO/AR, Bahnschrift→Roboto Condensed→Arial Narrow for quote/dn/inv. Eshraqat skin: **Aptos → Segoe UI → Arial for ALL doc types**. Only the APP UI CSS bundles fonts. If a target machine lacks Bahnschrift/Aptos the PDF silently falls back down the stack.

## Eshraqat print skin - static/eshraqat_print.css + templates/eshraqat/

**Purpose** - The complete second print skin used by ALL five doc types when `config.ACTIVE_PROFILE == "eshraqat"` (multi-company profile subsystem: [[13-PROFILES-BRANDS]]). One shared ~300-line stylesheet (`.esh-*` classes) + five Jinja templates + a shared macro library. The default (abraj) profile never touches these files.

> **The PO is the odd one out (2026-08-09).** Three of the four eshraqat documents are **English + LTR**; the **PO alone is Arabic + RTL**, has **no footer band**, and stacks its meta on the right. Its rules live in the `.esh-po-document` block at the end of `eshraqat_print.css` - see "Eshraqat PO (Arabic/RTL)" below before touching anything shared.

**Key symbols**
- **`static/eshraqat_print.css`** - own `@page` (8.8mm 8.75mm 15.9mm), `.esh-page` (192.5mm × min-height 270mm - see geometry note above), `.esh-table` (+ `--autofit`), `.esh-page-number`, its own `.sig-stamp`/`.sig-hand` variant. Brand red `#8f1730`; per-doc-type title colors via body class (quote black default, `.esh-dn-document` red `#8f1730`, `.esh-invoice-document` blue `#1f4e8f`). Brand color also arrives inline as `--brand` / `--esh-brand` from `config.PROFILE_ACCENT`. The trailing `.esh-po-document` block is the Arabic/RTL PO override set.
- **`templates/eshraqat/_components.html`** - shared Jinja macros, imported `with context` by all five eshraqat templates: `header()`, **`header_ar(title)`** (PO only - logo first so RTL puts it on the right, Arabic `identity.name_lines_ar` + title on the left), `meta_grid(rows)`, `table_header(columns)` (emits the inline `width: {{ c.width }}%`), `amount_totals(rows, words, currency)`, `terms_signing(terms, sig_html, label)` (contains the `.sig-box`), `footer()`, `page_number(idx, total)`, **`page_number_ar(idx, total)`** (PO only - "صفحة س من ص").
- **`templates/eshraqat/{po,quote,dn,inv}_page.html`** - per-doc templates built from the macros. Each also embeds a small per-doc inline `<style>` block (e.g. dn grand row, inv row height) and sets `--esh-row-mm` inline per page. `inv_page.html` carries a `data-invoice-type` attr.
- **`backend/eshraqat_render.py`** - `meta_rows(kind, doc)` is the ONE header layout for the Eshraqat quotation / DN / invoice (2026-10-02; see [[04-BACKEND-DOCGEN]]). `.esh-meta-wide` still exists in the CSS but no English document uses it any more - a full-width row breaks the two-column reading order, which is what put IV-0005's address in the wrong place. `common_context(title, doc_no, pages)` supplies the shared context: `{eshraqat: True, identity: config.ESHRAQAT_IDENTITY, brand: config.PROFILE_ACCENT, logo_data_uri (brand_assets.logo_data_uri(required=True)), iso_data_uri, document_title, document_no, page_count}`. **Raises `RuntimeError` if `ACTIVE_PROFILE != "eshraqat"`.**

**Generator coupling (pagination-critical)** - hard-coded chrome constants in the generators MUST track `eshraqat_print.css` header/meta/footer geometry or pagination overflows pages: `Q_ESH_PAGE_CHROME_MM = 34.0` (`quote_generator.py` ~125), `DN_ESH_PAGE_CHROME_MM = 34.0` (`dn_generator.py` ~86), `INV_ESH_PAGE_CHROME_MM = 34.0` (`inv_generator.py` ~73), `INV_ESH_CLOSEOUT_MM = 58.0` (`inv_generator.py` ~225). Guard: `tests/eshraqat_pagination_solidity.test.py`; rules: [[12-PDF-LAYOUT-CONSTITUTION]].

### Eshraqat PO (Arabic/RTL) - `templates/eshraqat/po_page.html` + the `.esh-po-document` CSS block

Redesigned 2026-08-09. The brief was "make the Eshraqat PO look like the Abraj PO, in Arabic", so it deliberately borrows the base skin's structure while keeping eshraqat's brand palette.

- **`<html lang="ar" dir="rtl">` + `<body class="esh-document esh-po-document rtl">`** - `rtl` flips the existing `.esh-document.rtl { direction: rtl }` rule (which pre-dated this and was unused). RTL flow is what places every "first" element on the right: the logo, the `ت` column, and `.esh-terms` (grid-column 1) all land right; `.esh-signature` (grid-column 3) lands left, like the base skin's bottom-left `.signature`.
- **Header** - `esh.header_ar(document_title)`. `document_title` is the ARABIC title: `pdf_generator` passes `config.ESHRAQAT_IDENTITY["po_title_ar"]` ("طلب شراء") into `common_context(title=…)` for this doc type only. Name lines come from `identity.name_lines_ar`; the four English skins still read `identity.name_lines`.
- **Meta** - `esh.meta_grid` with Arabic labels (`التاريخ`, `رقم طلب الشراء`, and `رقم عرض السعر` only when the PO has a source quotation). `.esh-po-document .esh-meta` collapses the shared 2-up grid to a single 52% column, which RTL parks on the right.
- **Table** - `ت · المادة · الوصف · الوحدة · العدد · الشركة · [صورة] · السعر` in source order, i.e. `ت` prints rightmost. Column widths are the **same reference percentages as `po_styles.css`** and live in the template's inline `<style>` (including the `.items-table.has-images` narrowing), so `_po_col_style`'s injected `.items-table .col-*` rules are overridden by the has-images set exactly as they are in the base skin. Body/head font is bumped to 9pt (the English skins' 7.5pt is too small for Arabic) and cells get an `inline-start` hairline so an 8-column table stays scannable.
- **Picture column** - same slot and same contract as the base skin: markup only when `page.has_images` (whole-document flag), `--po-img-mm` emitted on `.esh-po-document` from `pages[0].image_row_mm`, and a `max-height` cap that MUST agree with `pdf_generator.PO_IMAGE_ROW_MIN_MM`.
- **Closing zone** - translated: `الشركة المجهزة` + supplier, and `التوقيع المعتمد` over the signature line. Pinned to the bottom of the last page by a flex-column rule (`.esh-po-document .esh-closing-zone { margin-top: auto }`), the same trick `.esh-quote-document` uses. Without it a 4-row PO prints its signature - and the stamp overlay, which reaches ~13mm *above* its box - halfway up an empty page.
- **No footer band.** `esh.footer()` is not called, so the website/emails/ISO strip prints on no PO page; `esh.page_number_ar` is the only thing at the foot. Because the footer is gone, `.esh-po-document .esh-page` drops `padding-bottom` 20mm → 10mm, which is why **`pdf_generator.PO_ESH_USABLE_MM` is 260, not the 250 the other four skins imply**. Change the padding ⇒ re-measure that constant ([[12-PDF-LAYOUT-CONSTITUTION]] §8).
- **Never write "Abraj" into `eshraqat_print.css` or the eshraqat templates** - `tests/eshraqat_quote_rendering.test.py` asserts `"ABRAJ" not in html.upper()`, and the stylesheet is inlined into every eshraqat PDF, so even a *comment* fails them. Say "the default skin" / "po_styles.css".

**Gotchas**
- **PO numbering renders zero-padded to width 4 under eshraqat** (`pdf_generator.py` ~142: `f"{PO_PREFIX}-{n:04d}"`), unpadded otherwise.
- **The eshraqat PO is the only Arabic document in the skin.** A change to `header()`, `footer()` or `page_number()` does NOT reach it (it uses `header_ar` / no footer / `page_number_ar`), and a change to `header_ar` reaches nothing else.
- The page-number class is `.esh-page-number`, NOT `.page-number` - base-skin page-number fixes don't reach this skin.
- Aptos silently falls back Aptos → Segoe UI → Arial on machines without Aptos (still `@font-face`-free).

## static/app_styles.css

**Purpose** - The single global stylesheet for the entire desktop app UI (all 20 views). Defines the design-token system, fonts, and every view's chrome. This is the file `dark.css` re-themes.

**Key symbols** (section families, not individual rules - top-to-bottom order matters for the cascade):
- **Bundled `@font-face`** - `Noto Naskh Arabic` (constrained to Arabic `unicode-range` so Latin falls through) and `Roboto` (variable). Files under `static/fonts/`. This is the ONLY place app fonts are declared.
- **`:root` design tokens** - the entire theming contract: surfaces (`--bg`, `--surface`, `--surface-sunk`, `--bg-elev`, `--surface-2`), tables (`--header-tint`, `--header-ink`, `--zebra`, `--row-hover`), borders, text (`--text`, `--text-muted`, `--text-subtle`), accents (`--navy*`, `--brand`=`#002060`, `--success`/`--success-ink`, `--danger`, `--warn`), **the primary fill `--accent-fill` / `--accent-fill-hover` / `--on-accent` (2026-10-09)**, radii (`--r-sm..xl`), easings, shadows (`--shadow-xs..modal`), typography (`--font-ui`, `--font-ar`). **`dark.css` overrides a subset of these tokens; anything using `var(--token)` flips automatically.**
- **`body::before`** - GPU-composited fixed gradient background (comment explains it replaces `background-attachment:fixed` to avoid scroll repaint lag).
- **TOPBAR** - `.topbar`, `.brand`, `.home-btn`, `.actions`, `.actions-divider`, `.action-break`, `.prices-toggle` (sticky app header, universal editor action grouping; action groups compact and horizontally scroll instead of overlapping on narrow windows; DN prices behaves like a pressed toolbar toggle next to Fit rows). Quotation, DN and Invoice also expose `#btnQMasterFill` / `#btnDnMasterFill` / `#btnInvMasterFill` for the shared Master Data fill popup. The PO exposes `#btnPoMakeDn` / `#btnPoMakeInv` (2026-09-05) for the Make DN / Make Invoice flow.
- **UNIFIED DOCUMENT INFORMATION ROW (2026-08-24)** - `.doc-info-row` / `.doc-info-field` / `.doc-info-control` are the shared, non-wrapping metadata-bar geometry used by the **PO, quotation, DN and invoice** editors. Authoritative dimensions live once, in the `:root` tokens `--doc-info-control-h: 34px`, `--doc-info-label-size: 11px`, `--doc-info-row-gap: 10px` (also the literal `column-gap`), `--doc-info-field-gap: 4px`:
  - `.doc-info-row` is a `display:grid`, `align-items:end`, 10px `column-gap` bar; each document keeps **only** its own `grid-template-columns` - one `minmax(<px floor>, <fr>)` track per field: `.quote-meta-form.doc-info-row` 6, `.dn-meta-form.doc-info-row` 7, `.inv-meta-form.doc-info-row` 8. `.po-strip.doc-info-row` sizes its **three** fields with capped `minmax(px, px)` tracks and ends in a **`1fr` filler** - a filler rather than a `max-width`, so the strip stays a full-width band and its bottom border still runs edge to edge while the fields keep a sane width on a wide monitor (in RTL the filler lands on the left, so fields hug the start edge). The px floors stop a field being crushed; there is **no** `repeat(auto-fit,…)` fallback and no narrow-width `@media` that re-wraps DN/INV. Verified in real Chromium: no overflow down to a 900px window. The Open panel still collapses at its existing breakpoint.
  - `.doc-info-field` standardizes the label/control stack (flex column, bottom-aligned, 4px gap) and **zeroes the legacy framed-chip chrome** (padding/border/background) on the old `doc-no-field`/`doc-reference-field`/`doc-quote-field`/`doc-date-field`/`po-links-field` wrappers; identity emphasis now lives on the input text only.
  - `.doc-info-control` owns the 34px height, border, typography and focus ring; it also rides the composite `.qf-link` wrapper while the contained input keeps its own `.doc-info-control` for typography.
  - **Gotchas - four rules outranked the shared geometry and each produced a visible glitch (all fixed 2026-08-24; re-check these before adding a control to a row):**
    1. **`#invBank` is an ID rule (1-0-0)** and beats every `.doc-info-*` class rule, so its `height:38px` left the invoice Payment Bank 4px proud of its peers. The ID rule now carries the shared tokens itself.
    2. **`.date-input`** (the legacy dashed-underline treatment, defined ~line 3340, far below the shared block) matches `.doc-info-control` at **equal specificity** and therefore won on source order - its `min-width:130px` stopped date tracks shrinking and pushed the dense invoice row out of alignment. Overridden by `input[type="date"].doc-info-control` (0-2-1), which wins regardless of order.
    3. **`height:100%` inside `.doc-info-field`** resolves against an *auto-height* flex column, i.e. to the control's own content height (26px, not 34px). Always use `height: var(--doc-info-control-h)`, never a percentage.
    4. **`.po-strip .po-extra:empty`** must stay `display:none` - an empty span still consumes the field's 4px column gap and makes رقم الطلب the one field taller than its neighbours.
- **PO INFO STRIP** - `.po-strip`, `.po-no`, `.doc-no-field`, `.doc-reference-field`, `.doc-date-field`, `.po-extra`, `.mode-chip`, `@keyframes pulseDot` - the PO-number / Reference / date band on `editorView`, now a `.doc-info-row` grid rather than a wrapping flex strip. **2026-08-24 - the strip was cut to these three fields:** the `ربط عرض السعر` quotation-link field and the `الربط` DN/Invoice fulfillment buttons were removed at the user's request, and their now-dead CSS (`.po-quote-field` / `.po-quote-control` / `.po-quote-input` / `.po-quote-pick`, and the Phase Y.7 `.po-links-*` / `.po-link-cta` / `.po-link-count` families) was deleted with them. **The link data is unaffected** - `source_quote_no` still loads into `state.sourceQuote` and is written back on save, so existing PO->quotation links survive a round-trip, and DN/Invoice-side linking is untouched ([[05-FRONTEND-SHELL]]).
- **VIEW WRAPPER** - `.view` (full-width view padding).
- **BUTTONS** - three hierarchies + async loading state; icon-only square button; editor workflow buttons (`.doc-flow-btn`) share one blue family. **2026-10-09 (Waleed: "not ok with that green button with white font"):** `button.primary` fills with `--accent-fill` (blue, white ink 5.17:1) instead of `--success` green (3.77:1 light, 1.89:1 dark); the Back button (`button.warm-red`, class kept so no markup moved) is now the neutral secondary treatment, not a coral slab; `.editor-save-btn.is-saved` / `.sig-btn.is-signed` are a STATE tint (`--success-soft` + `--success-ink`), not a solid green button; Won / Mark-paid style actions fill blue, never green beside a red Lost (colour-blind rule). **Gotchas**

- **`--brand` (#002060) is reserved for PDF/PO-number display**, NOT general UI - the softer `--navy` is the UI accent. Don't swap them.
- Section headers are labeled by "Phase" (H, I, K.1, M.x, N, O, Q, X.x). Source order = cascade order; late phases intentionally override earlier ones.
- **Never write a component background as a literal white** (`#fff`, `white`, or `white` as the far end of a `color-mix`) - write `var(--surface)`, which IS `#ffffff` in light mode and the dark surface in dark mode. 2026-10-09 converted 69 such rules (To-Do, Needs attention, PO/type settings popups, pills, filter chips...) that had been painting white slabs into dark mode. `tests/dark_mode_contrast.test.js` fails on a new one; its short allowlist is the intentional white mats (logo, signature, scanned page, switch knob).

## static/dark.css

**Purpose** - Dark theme overlay. ~660 lines. Active ONLY when `<html data-theme="dark">`. Loaded AFTER `app_styles.css` (and costing) so it wins by source order + the extra `html[data-theme="dark"]` specificity. Light mode untouched.

**Theming mechanism (important)**

**Purpose** - Default-skin Jinja PDF template for Delivery Notes. Rendered by `backend/dn_generator.py` (eshraqat profile uses `eshraqat/dn_page.html` instead). Styled by `dn_styles.css`. Near-identical skeleton to quote, minus terms, with a two-box signature footer.

**Structure** - `.dn-page` per page; `.d-header`/`.d-meta` on `show_header`; `.d-table` (columns from schema, per-page `--dn-row-mm`); grand-total row (`.d-grand-row`) rendered INSIDE `<tbody>` (not tfoot) when `grand_total and page.show_footer`. Footer = two `.d-sign` boxes: **left = Recipient (bare, no overlay - client hand-signs on receipt)**, right = Supplier (`.sig-box` + `sig_overlay_supplier`).

**Context vars** - `pages`, `columns`, `dn.{dn_no,date,client_name,client_address,lpo_no}`, `company.{name_lines,title,closing,recipient_label,supplier_label}`, `grand_total`, `brand`, `logo_data_uri`, `autofit`, `sig_overlay_supplier`.

**Gotchas**
- Recipient box is intentionally left unsigned (explicit comment) - uses `sig_overlay_supplier` for the supplier side only, NOT `sig_overlay_main`.
- Grand total lives in `<tbody>`, unlike quote (`<tfoot>`) - a subtle divergence between two otherwise-parallel templates.

## templates/inv_page.html  (LTR English)

**Purpose** - Default-skin Jinja PDF template for Invoices. Rendered by `backend/inv_generator.py` (eshraqat profile uses `eshraqat/inv_page.html` instead). Styled by `inv_styles.css`. Adds a withholding-tax row, total row, and a bank/payment card.

**Structure** - `.inv-page` per page; header/meta on `show_header`; title is `{{ schema_label }}` (e.g. "Tax Invoice"). `.i-table` columns from schema (per-page `--i-row-mm`, default 14mm). On `show_footer`: an `.i-tax-row` (`tax_label_span`, `company.tax_label`/`tax_status_label`) + `.i-total-row` (`total_label_span`/`total_words_span`/`total_amount_span`, `grand_words`/`grand_amount`) inside tbody. Footer: `.i-payment` bank card - full bank lines when `bank` present, else **"PAID IN CASH"** (`.i-payment-cash`, Phase G.12); plus `.i-sign.sig-box` with `sig_overlay_main`.

**Context vars** - `pages`, `columns`, `inv.{inv_no,date,client_name,client_address,lpo_no}`, `schema_label`, `company.{name_lines,closing,tax_label,tax_status_label,signature_label,signature_name}`, `bank.{company_line,bank_name,branch,swift,account_no,iban,currency}`, `grand_words`, `grand_amount`, tax/total span vars, `brand`, `logo_data_uri`, `autofit`, `sig_overlay_main`.

**Gotchas**
- Cash vs bank branch: `{% if bank %}…{% else %}PAID IN CASH{% endif %}` - generator passes `bank=None`/`"cash"` for cash invoices. `.i-payment-cash` styling is a separate green band.
- Each bank line (`branch`, `swift`, `iban`, etc.) is individually `{% if %}`-gated - missing fields collapse cleanly.
- Tax + total rows are inside `<tbody>` (like dn), spans computed in Python.

## static/master_doctor.css - the catalogue review panel (2026-09-10)

Styles the `.mdoc-*` panel built by `static/master_doctor.js` ([[07-FRONTEND-SUPPORT]]). Loaded from `index.html` beside `item_review_popup.css`.

**The one rule that matters here:** colour never carries meaning alone. `.mdoc-warn` is an amber rule and tint beside the sentence *"The copies disagree about the price"* - the words are the message and the colour is reinforcement. **There is no green counterpart**, and `tests/master_doctor_screen.test.js` asserts that against the stylesheet's declarations with the comments stripped out, because the file's own comment contains the word.

Reuses the screen's existing `.im-btn`, `.im-btn-primary`, `.im-btn-xs` and `.im-chip` so the review does not invent a second button language. Collapses to one column under 820px.

## static/gate.css - switch animations (2026-10-07)

- **Ring round the seal:** `<i class="gate-orbit">` in each `.gate-seal` (index.html AND tests/gate_qa.html - the copy is enforced) draws a conic band filled to `--gate-sweep` (registered `@property`, inherits), set by gate.js with the bar's own easing. One round, no head, nothing spins - same as the native gate.
- **Colour wash:** `.gate-wash` (made by gate.js) spreads the new company's gradient from the seam (`clip-path: circle()` from `100% 50%`). The brand door's background reads `--gate-door-accent` (falls back to `--gate-accent`) so it keeps the OLD colour until the wash covers it, while the ring, bar and seal change with the logo.
- **Logo swap:** `#gate.is-swap-out` / `.is-swap-in` blur + scale the seal logo and the brand words out and in.
- **Depth:** doors dim to `brightness(0.88)` while parting; `html.gate-reveal` / `.gate-revealing` settle `body > header/main/nav/aside/.view` from 98.5% for the length of the slide. All of it is off under `prefers-reduced-motion`.

## Stamp and signature run into the name (2026-10-07)

Each print stylesheet's `.sig-overlay` declares `--sig-text-h` (the printed title + name block under the signature line: `quote_styles.css` 10.2mm, `dn_styles.css` 4.2mm, `inv_styles.css` 9.5mm, `po_styles.css` 10mm, `eshraqat_print.css` 4.2mm) and `.sig-stamp, .sig-hand` carry `mix-blend-mode: multiply`. `signing.render_overlay_html` positions both with `calc(var(--sig-text-h) * fraction - gap)` so the ink always ends inside that block ([[04-BACKEND-DOCGEN]]). Edit a signature box's lines -> re-measure that value.

`app_styles.css` adds `.in-hero-tools` / `.in-stmt*` (the Monthly statement popup) and `.verify-*` (Verify a document: the verdict is a WORD; red only beside NOT GENUINE, never a red/green pair - [[waleed-colour-blind]]).
